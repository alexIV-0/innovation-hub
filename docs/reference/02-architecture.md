## 1. Общая схема

```
                    браузер                          парк машин (fs.manager.tauri)
                       │                                        │
                cookie inhub_session                  Bearer mch_… / rc_…
                       │                                        │
        ┌──────────────┴──────────────┐            ┌────────────┴────────────┐
        │                             │            │                         │
   страницы (RSC)              /api/* роуты   /api/storage/v1/*        POST /api/v1
        │                             │            │                         │
        └──────────────┬──────────────┴────────────┴─────────────────────────┘
                       │
        ┌──────────────┴───────────────────────────────────┐
        │   доменные модули (lib/)                         │
        │   storage · pipeline · statistics · options ·     │
        │   markdown · tools · repositories                │
        └──────────────┬───────────────────┬───────────────┘
                       │                   │
                 PostgreSQL          Cloudflare R2
                (истина о том,       (истина о байтах)
                 что существует)
```

Плюс три исходящих канала: YouGile (чат), Resend (письма), Web Push
(уведомления).

## 2. Слои и где что лежит

| Слой | Папка | Правило |
| --- | --- | --- |
| Маршруты и страницы | `app/` | тонкие. Страница получает данные и отдаёт их клиентскому компоненту; роут авторизуется, валидирует и зовёт доменный модуль. |
| Представление | `components/` | по зонам: `landing`/`site`/`videos` — публичный сайт, `account/*` — кабинет, `admin/*` — админка, `ui/*` — примитивы, `markdown/*` — редактор и просмотрщик описаний. |
| Домен | `lib/` | вся содержательная логика. Не знает про `NextRequest` — кроме модулей, которые специально этим и занимаются (`lib/storage/auth.ts`, `lib/*-endpoint.ts`). |
| Данные | `lib/repositories/`, `lib/storage/`, `lib/db.ts` | SQL живёт только здесь. |

### Именованные подсистемы в `lib/`

| Папка | Что внутри |
| --- | --- |
| `lib/storage/` | путь записи в хранилище, ключи, имена, журнал, корзина, копирование, multipart, фоновые работы |
| `lib/pipeline/` | сканер, обход, очередь задач, сборка объекта обработки, состояние |
| `lib/statistics/` | суточные срезы, импорт/экспорт архива обработок, часовой тик |
| `lib/machine-api/` | реестр экшенов `POST /api/v1`, обработчики, каталог документации |
| `lib/options/` | разбор и правка `options.json` (параметры, отданные на сайт) |
| `lib/markdown/` | конвейер markdown, команды тулбара, две реализации редактора |
| `lib/tools/` | каталог инструментов и модель документа `dialog.json` |
| `lib/mail/` | шаблоны и отправка писем |
| `lib/repositories/` | по одному модулю на сущность |

## 3. Два источника правды, и это осознанно

| Что | Где истина | Почему так |
| --- | --- | --- |
| Байты файла | R2 | их больше нигде и не может быть. |
| Существование файла, имя, путь, размер | Postgres `project_files` | листинг бакета стоит денег и времени и не знает, кто залил файл. |
| Порядок событий | Postgres `storage_changes` (`BIGSERIAL seq`) | монотонный курсор — основа инкрементальной синхронизации и событийного сканера конвейера. |
| Тумблер слежения проекта | **R2** `options/folderState.json` | этот файл читает десктопное приложение. В Postgres (`projects.is_paused`) лежит зеркало для быстрых выборок; владеет обоими `lib/project-automation.ts#setProjectPaused`, а `reconcileProjectPauseFromFolderState` подтягивает кэш, если объект правили в обход. |
| Параметры обработки | **R2** `options/options.json` | формат задаёт редактор нод десктопа; сайт правит только помеченные `exposedToSite` свойства. |
| Развёрнутое описание | **R2** `options/description.md` | пишется и читается обеими сторонами. Короткая подпись остаётся в `projects.description`, чтобы список проектов не ходил в R2 на каждый рендер. |
| Общие словари типов и цветов | Postgres `automation_settings` (синглтон) | принадлежат системе обработки, а не клиенту; оптимистическая блокировка по `revision`. |

Правило: **если файл читает внешняя программа — истина в файле**; Postgres в
таком случае держит зеркало, и владелец записи один.

## 4. Модель рендеринга

- Серверные компоненты по умолчанию. `"use client"` — там, где есть состояние,
  события или браузерные API.
- Почти все страницы кабинета и админки объявляют `export const dynamic =
  "force-dynamic"`: они персональны, кешировать нечего.
- Публичные страницы тоже `force-dynamic`, но данные внутри завёрнуты в
  `unstable_cache` с тегом `published-videos` и `revalidate: 60`. Админские
  мутации зовут `revalidateTag("published-videos", "max")` — инвалидация
  мгновенная, 60 секунд это страховка.
- `Suspense` + `loading.tsx` — там, где часть страницы ждёт медленный запрос
  (например, `app/account/dashboard/page.tsx` отдаёт скелет под проекты).

### Оптимизация картинок

`next.config.mjs`:
- форматы `avif`, `webp`; разрешённые `qualities: [30, 70, 75]` (30 нужен
  размытому фону карточки);
- `localPatterns` разрешает только `/api/media/**?raw=1` и статику из `/public`;
- `remotePatterns` — `cdn.ffworks.pro`, `*.r2.cloudflarestorage.com`,
  legacy `s3.twcstorage.ru`;
- `minimumCacheTTL` — сутки: `/api/media` отдаёт короткоживущий redirect, и без
  длинного кеша оптимизатор перекачивал бы оригиналы.

## 5. Путь запроса

### Страница админки

```
GET /admin/pipeline
  → proxy.ts        : cookie есть? JWT валиден? role === ADMIN?  (без БД)
                      + Cache-Control: no-store на всю зону /admin
  → app/admin/layout.tsx : getCurrentUser() — один запрос в БД,
                           повторная проверка isActive и роли
  → страница        : серверный компонент, отдаёт клиентский PipelineContent
```

Почему проверка дважды: в `proxy.ts` только дешёвый JWT (иначе на каждую
навигацию — round-trip в Postgres), а авторитетная сверка с базой — один раз в
layout и в каждом `/api/admin/*` через `requireAdminApi`. Заблокированный или
разжалованный админ отлетает сразу.

### API-роут кабинета

```
PATCH /api/projects/:id
  → requireUserApi(request)               — сессия, активность аккаунта
  → requireProjectAccess(id, userId, "editor")  — роль в проекте
  → zod-схема из lib/project-schemas.ts
  → доменный модуль (lib/storage/project-mutations.ts, lib/project-automation.ts)
  → NextResponse.json
```

### Машинный вызов

```
POST /api/v1  { action, props, token }
  → dispatchMachineApi (lib/machine-api/dispatch.ts)
      1. токен → authenticateComputerToken  (только rc_…)
      2. action → ACTION_REGISTRY
      3. props  → zod-схема экшена
      4. handler.run(auth, props)
```

Один эндпоинт вместо REST — потому что клиент один (десктоп), и добавление
возможности не должно требовать нового пути и нового раунда согласований.

## 6. Фоновые циклы

Поднимаются в `instrumentation.ts` один раз при старте процесса, только в
Node-рантайме. Это работает потому, что приложение — долгоживущий процесс под
pm2. **В serverless эта архитектура не поедет.**

| Цикл | Модуль | Период | Что делает |
| --- | --- | --- | --- |
| Поллер чата | `lib/chat-push-poller.ts` | — | тянет ответы команды из YouGile. Нужен потому, что вебхук YouGile не срабатывает на сообщения, набранные в самом YouGile. |
| Раннер конвейера | `lib/pipeline/runner.ts` | 15 с | собирает протухшие аренды задач, сиротские задачи; при включённом слежении — событийная сборка задач, по расписанию — обход папок IN. |
| Тик статистики | `lib/statistics/stats-loop.ts` | 1 ч (первый — через 30 с) | суточный срез объёма, импорт архива обработок из R2, месячный экспорт копии архива. |

Плюс одноразовый идемпотентный сид общих словарей — не `await`, чтобы не
задерживать старт.

Дополнительно: каждый цикл читает свой флаг **из базы**, а не держит в памяти.
Закрытая страница не останавливает конвейер, перезапуск процесса возобновляет
его, несколько админов видят одно состояние.

### Ручные входы в те же процедуры

| Роут | Что запускает |
| --- | --- |
| `POST /api/cron/storage-jobs` | разбор очереди фоновых работ + чистка корзины |
| `POST /api/cron/storage-purge` | чистка корзины + суточный срез + импорт/экспорт архива |
| `POST /api/admin/pipeline/collect` | разовая событийная сборка задач |
| `POST /api/admin/pipeline/sweep` | разовый обход папок IN |
| `POST /api/admin/statistics/import` | разовый импорт архива обработок |

Авторизация cron-роутов: `Authorization: Bearer $CRON_SECRET` **или** сессия
админа. Кто дёргает их по расписанию — из репозитория не видно, `CRON_SECRET`
нигде не настраивается. Именно поэтому критичные вещи (суточный срез) живут в
процессе: пропущенный день невосстановим.

## 7. Состояние в памяти процесса

Три места, из-за которых нельзя поднять второй инстанс без переделки:

| Что | Где | Последствие масштабирования |
| --- | --- | --- |
| Rate limit | `lib/rate-limit.ts` — `Map` в модуле | лимит станет N-кратным по числу инстансов. |
| Флаги «цикл уже запущен» | `runner.ts`, `stats-loop.ts`, `chat-push-poller.ts` | циклы задублируются; сами операции идемпотентны, но нагрузка на YouGile и R2 вырастет. |
| Кеш «этого чата в YouGile больше нет» | `lib/project-chat-sync.ts` — `Set` | не критично. |

Планируемая замена rate limit на Redis/KV помечена в самом файле.

## 8. Три поверхности одной логики

Одни и те же операции над проектом доступны из трёх мест с разной авторизацией:

| Поверхность | Авторизация | Кто ходит |
| --- | --- | --- |
| `/api/projects/*`, `/api/account/*` | cookie сессии | браузер кабинета |
| `/api/storage/v1/*` | cookie **или** `Bearer mch_…` / `Bearer rc_…` | десктоп-клиент, браузер (частично) |
| `POST /api/v1` (экшены) | `rc_…` в теле | машины парка |

Где это сделано правильно — логика вынесена в общий модуль, а роуты остались
тонкими:

- очередь задач → `lib/pipeline/queue-endpoint.ts`
- общие словари → `lib/settings-endpoint.ts`
- проекты (создать/переименовать/состояние/удалить/восстановить) →
  `lib/storage/project-mutations.ts` + `lib/storage/project-catalog.ts`
- multipart → `lib/storage/multipart.ts`
- корзина, копирование, фоновые работы → `lib/storage/{trash,copy,jobs}.ts`

Где не сделано — обработчик скопирован в оба места: `presign`, `notify`,
`mkdir`, `rename`, `deleteObject`, `reindex`, `sidecars`. Две копии **уже
разошлись**, разбор — [14](./14-improvements.md#1-две-поверхности-одного-storage-api-разошлись).

## 9. Обработка ошибок: принятые соглашения

| Ситуация | Ответ | Где решается |
| --- | --- | --- |
| Нет сессии | 401 | `requireUserApi` / `requireAdminApi` |
| Аккаунт заблокирован | 403 | там же |
| Не админ на `/api/admin/*` | 403 | `requireAdminApi` |
| Нет доступа к проекту (кабинет) | **404** | `lib/project-access.ts` — чужой проект не подтверждает своё существование |
| Доступ есть, роль ниже нужной (кабинет) | **403** с текстом | там же — человек проект видит и должен понять, почему кнопка не сработала |
| То же в машинном протоколе | **404** в обоих случаях | `lib/storage/auth.ts` — контракт `/api/storage/v1/*` менять нельзя |
| Занятое или недопустимое имя | 409 / 400 | `StorageWriteError` из `lib/storage/errors.ts` |
| R2 не настроен | 503 | `isS3Configured()` |
| Схема БД устарела | 503 с инструкцией «прогони db:migrate» | `app/api/projects/route.ts`, `app/api/auth/signin/route.ts` |
| Вебхук YouGile: что угодно | **всегда 2xx** | YouGile ретраит на не-2xx; плохое событие не должно ронять приём |

`StorageWriteError` носит `status` внутри себя — поэтому доменный модуль может
сказать «409, имя занято», не зная про HTTP.
