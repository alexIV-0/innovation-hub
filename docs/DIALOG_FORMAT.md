# Диалоговый документ: формат `dialog.json`

> Контракт между локальным клиентом (`fs.manager.tauri`) и сайтом. Составлен 2026-08-24.
> **Этот файл — канонический текст правил.** В репозитории клиента лежит
> `fs.manager.tauri/ideasAndTest/DIALOG_FORMAT_CONTRACT.md`: ссылка сюда плюс клиентская
> специфика (транспорт, конкурентность по `mtime`, вотчер). Правила там намеренно не
> дублируются — два полных текста разъезжаются молча, а формат здесь единственное, что
> связывает две независимые реализации.
>
> **Зачем формат, а не SRT.** Материал — реплики нескольких персонажей: у каждой есть дорожка,
> тайминги, оригинал, переводы на несколько языков, статус вычитки и задел под озвучку. SRT
> не умеет ничего из этого, кроме таймингов и текста, а перенос реплики с дорожки на дорожку в
> нём выражается как несколько правок в нескольких файлах, которые обязаны получиться
> одновременно. Поэтому источник правды — один документ, а SRT / VTT / формат для Reaper —
> **экспорт** из него (§7).
>
> **Две реализации, один формат.** Редактор существует дважды: на сайте
> ([TOOLS_SRT_EDITOR_PLAN.md](./TOOLS_SRT_EDITOR_PLAN.md), работает с онлайн-папкой проекта) и
> в программе (`ideasAndTest/DIALOG_EDITOR_PLAN.md`, работает с локальной папкой, в том числе
> в контуре NDA). Общего кода UI у них нет и не будет — стеки разные. Синхронизируется
> **контракт**, а не код: тот же приём, что с описанием проекта
> ([DESCRIPTION_FORMAT.md](./DESCRIPTION_FORMAT.md)) и портом движка очереди
> ([lib/pipeline/process-queue.ts](../lib/pipeline/process-queue.ts)).
>
> Эталонный файл рядом: [dialog.example.json](./dialog.example.json).

## 1. Артефакт

| что | значение |
|---|---|
| имя файла | `dialog.json` в корне папки задачи |
| кодировка | UTF-8, без BOM, переводы строк `\n` |
| отступ | 2 пробела, ключи — в порядке, объявленном в §3 |
| источник истины | сам файл. В Postgres документ не дублировать вторым источником — только кэш, если понадобится |
| канал (сайт) | обычный файл проекта: `presign` → PUT → `notify`; конкурентность — `ifMatch` по ETag (§8) |
| канал (программа) | запись на диск; конкурентность — `mtime` + `size` перед перезаписью |
| кто создаёт | нода графа обработки (`dialogDocBuild`), см. [TOOLS_SRT_EDITOR_PLAN.md §V.5](./TOOLS_SRT_EDITOR_PLAN.md) |
| кто правит | оба редактора; ноды после создания документ **не перезаписывают** (§9) |
| размер | ~1 МБ на час материала с двумя языками. Файл читается и пишется целиком |

Имя файла — часть контракта. Менять его = править ноду, обе реализации и все экспортёры.

## 2. Девять правил, без которых две реализации разъедутся

Это самая важная часть документа. Всё остальное — перечисление полей.

**1. Время — целые миллисекунды.** Никаких секунд с плавающей точкой: `26.27` в одной
реализации станет `26.269999999999996` в другой, и сравнение таймингов начнёт врать.
Покадровая привязка, где нужна, считается из `media.fps` в момент отображения, а не хранится.

**2. `endMs` эксклюзивен.** Реплики `[1000, 2000)` и `[2000, 3000)` **не** пересекаются.
Без этого правила два редактора по-разному ответят на вопрос «есть ли наложение».

**3. Идентификаторы непрозрачны.** `id` — строка без семантики: не парсить, не выводить из неё
порядок, не показывать человеку. Единственная операция — сравнение на равенство.

**4. Порядок записи детерминирован:** реплики сортируются по `startMs`, при равенстве — по
`trackId`, при равенстве — по `id`. Дорожки — по `no`. Иначе два редактора пишут один и тот же
по смыслу файл разными строками, и любой diff превращается в кашу.

**5. Неизвестные поля сохраняются.** Читая документ, реализация обязана сохранить все поля,
которых не знает, и записать их обратно — на уровне документа, дорожки и реплики. Это
единственное, что позволяет двум сторонам развиваться независимо: программа добавила поле под
озвучку — сайт не должен его потерять при сохранении.

**6. Внутри major-версии только добавления.** Новое поле — можно, если старая реализация
корректно работает без него. Смена смысла или типа существующего поля = новый `version`, и обе
стороны обязаны отказаться открывать неизвестный major с внятным сообщением, а не пытаться
угадать.

**7. Пути внутри документа — относительные, только вперёд.** `01/audio.wav`, никаких `..` и
никаких абсолютных путей. Документ должен переживать копирование папки и одинаково работать
локально и онлайн. Реализация обязана отклонить путь с `..`, ведущим слэшем или буквой диска.

**8. Состояние интерфейса в документе не хранится.** `muted`, `solo`, `hidden`, высота дорожки,
масштаб таймлинии, выбранный язык — это состояние **одного человека за одним экраном**, и в
общем файле оно порождает конфликты и лишние записи на каждое движение мыши. Хранить локально
(`localStorage` на сайте, LS в программе) по ключу «id документа + id дорожки». В документе —
только то, что влияет на результат: имя дорожки, порядок, цвет.

**9. Экспорт — производная, никогда не источник.** Ни один экспортированный файл не читается
обратно в документ. Повторный экспорт профиля полностью перезаписывает свои файлы.

## 3. Структура

```jsonc
{
  "format": "dialogDoc",
  "version": 1,
  "id": "dd_9f2c7a1e",                    // непрозрачный id документа
  "revision": 42,                         // +1 на каждую запись, любой стороной
  "updatedAt": "2026-08-24T10:00:00.000Z",
  "updatedBy": "aleksey.ivanov@id.thesoul.io",   // человек или "node:dialogDocBuild"
  "producer": "innovation-hub/srt-editor 0.1",   // кто писал последним — для диагностики

  "media": {
    "video": "source.mp4",                // необязательно
    "mix": null,                          // общий звук отдельным файлом, если он есть
    "peaks": "mix.peaks.json",            // необязательно: волна общего звука
    "durationMs": 718400,
    "fps": 25                             // необязательно
  },

  "languages": {
    "original": "en",                     // ISO-639-1 или BCP-47
    "targets": ["es", "fr"]               // порядок = порядок колонок в редакторе
  },

  "rules": {                              // правила этого документа (§5)
    "maxCps": 25,
    "maxTranslationRatio": 1.2,
    "minDurationMs": 250,
    "minGapMs": 80,
    "overlapWithinTrack": "forbid"        // forbid | warn
  },

  "tracks": [
    {
      "id": "t01",
      "no": 1,                            // номер = имя папки дорожки ("01")
      "name": "Anna",                     // имя персонажа; попадает в имена экспортов
      "color": "#5B8DEF",
      "audio": null,                      // необязательно: у дорожки персонажа
      "peaks": null,                      //   своего звука может не быть вовсе
      "diar": {                           // необязательно: откуда взялась дорожка
        "engine": "sherpa-onnx 1.10.0",
        "speaker": "s0",                  // id спикера в diarization.json
        "confidence": 0.86                // средняя по репликам дорожки
      },
      "voice": { "provider": null, "voiceId": null, "params": {} }   // задел под озвучку
    }
  ],

  "cues": [
    {
      "id": "c_7f3a2b91",
      "trackId": "t01",
      "startMs": 26270,
      "endMs": 29190,
      "text": "So these guys just disappeared.",
      "tr": {
        "es": { "text": "Así que estos tipos simplemente desaparecieron.", "status": "draft" }
      },
      "status": "auto",                   // auto | edited | approved | conflict
      "rev": 3,                           // +1 на каждую правку этой реплики (для слияния)
      "origin": {
        "kind": "auto",                   // auto | manual
        "file": "01/orig.srt",            // откуда пришла реплика
        "index": 1,
        "speaker": "s0",                  // необязательно: спикер диаризации
        "confidence": 0.62                // необязательно: уверенность атрибуции
      },
      "movedFrom": "t02",                 // необязательно: откуда перенесли
      "note": "",
      "voice": { "takes": [] }            // задел под озвучку
    }
  ],

  "removed": [
    { "id": "c_2b91ff02", "at": "2026-08-24T10:00:00.000Z" }
  ],

  "mergedTracks": [
    { "from": "t05", "into": "t01", "at": "2026-08-24T10:05:00.000Z" }
  ]
}
```

### Обязательное и необязательное

| поле | обязательно | если отсутствует |
|---|---|---|
| `format`, `version`, `id`, `revision` | да | файл невалиден, открывать нельзя |
| `media.durationMs` | да | длину брать из медиафайла и записать при первом сохранении |
| `media.video` | нет | кадр не показывается, в превью остаются только титры |
| `media.mix` | нет | общий звук — звуковая дорожка видео; если нет и видео, звука нет вовсе |
| `media.peaks` | нет | волна не рисуется, таймлиния показывает линейку и клипы |
| `media.fps` | нет | покадровая привязка недоступна, шаг ±100 мс |
| `languages.original` | да | считать `"und"` и показать предупреждение |
| `languages.targets` | да (может быть пустым) | колонок перевода нет |
| `rules` | нет | значения по умолчанию из §5 |
| `tracks[].audio` | нет | **обычный случай**: дорожка персонажа — это его титры, отдельного звука у неё нет (§4) |
| `tracks[].peaks` | нет | на дорожке рисуется общая волна из `media.peaks` — приглушённо и с пометкой «общая» |
| `tracks[].voice`, `cues[].voice` | нет | зарезервировано под инструмент озвучки; **сохранять как есть** |
| `cues[].tr` | нет | перевода нет — колонка пустая |
| `cues[].origin` | нет | реплика создана человеком |
| `removed` | нет | пустой список |
| `mergedTracks` | нет | пустой список; см. §4 — без него повторный прогон вернёт разъединённые дорожки |

## 4. Смысл полей, который легко понять неправильно

**`removed` — не корзина, а прививка от воскрешения.** Нода `dialogDocBuild` умеет дописывать
документ новыми репликами из свежих SRT (§9). Если реплику удалил человек, а в SRT она осталась,
без списка `removed` она вернётся при следующем прогоне. Хранится только `id` и время; текст не
хранится — восстановление удалённого делает undo редактора, а не документ.

**`rev` у реплики — для слияния, а не для истории.** Две реализации могут править документ по
очереди (человек на сайте, потом человек в программе). При расхождении сравниваются `rev`
конкретных реплик, а не весь файл: у кого больше — того правка новее. История правок в
документе не живёт (§11).

**`status: "conflict"`** ставится только слиянием (§8) и означает «двое правили одну реплику,
победил один — посмотри глазами». Человек снимает его, поправив реплику.

**`origin` — связь с сырьём, а не путь для чтения.** Показывает, из какого файла реплика
пришла при импорте. Реализация не обязана этот файл открывать; он может быть удалён.

**Дорожка — это персонаж, а не аудиофайл.** Дорожку определяют её реплики; `audio` и `peaks` у
неё необязательны и в обычном случае пусты. Разделять исходный звук по персонажам ради
редактора не нужно: одного общего звука (дорожка видео или `media.mix`) достаточно, чтобы
слышать материал и ставить тайминги — редактор нарисует общую волну на каждой дорожке.
Отдельные стемы имеют смысл там, где они понадобятся дальше (например инструменту озвучки);
тогда поля заполняются, и дорожка показывает уже свою волну вместо общей.

Крайний случай, который тоже обязан работать: **звука нет вообще**. Тогда таймлиния показывает
линейку и клипы, превью — только титры, а инструмент остаётся полезным: тайминги и текст
правятся и так.

**Дорожка `no: 0` — «не распознано», и она особая.** Автоматика не всегда может приписать
реплику персонажу: короткое слово, шум, речь поверх речи. Терять такой текст нельзя, поэтому он
кладётся на зарезервированную дорожку `no: 0` (`id: "t00"`, имя по умолчанию «Не распознано»).
Правила: в экспорт по умолчанию она не попадает, а редактор
показывает её первой и предлагает разнести реплики по персонажам. Пустая дорожка `t00` в
документе не хранится.

Аудио у неё может быть: если обработка отдала стем нераспознанной речи, он подключается как у
любой дорожки — слушать такие реплики полезно именно затем, чтобы приписать их персонажу.

**`origin.confidence` — не украшение, а порядок работы.** Диаризация ошибается предсказуемо: чем
ниже уверенность, тем выше шанс, что реплика приписана не тому. Редактор сортирует по этому
полю в фильтре «требует внимания», и человек правит сначала сомнительное, а не читает всё
подряд. Поэтому поле пишется всегда, когда атрибуция машинная.

**`mergedTracks` — против дробления одного человека на несколько дорожек.** Это самая частая
ошибка автоматики: в реальном прогоне Cast Analyzer на «Moneyball» получилось 9 дорожек на ~7
настоящих говорящих, на «The Big Short» — 12 на ~7. Человек в редакторе объединяет лишние
дорожки в одну, и документ обязан это запомнить: иначе следующий прогон ноды снова создаст
`t05`, и работу придётся повторять. Запись `{ from, into, at }` говорит: «дорожка `t05` больше не
существует, её реплики теперь на `t01`». Реплики при объединении получают `movedFrom`.

Обратная ошибка — двое склеены в одну дорожку — отдельной записи не требует: человек создаёт
новую дорожку и переносит на неё реплики, а это уже описанные операции.

**`no` у дорожки — то же число, что имя её папки.** Дорожка `no: 1` живёт в папке `01`.
Номера не переиспользуются: удалили дорожку `02` и создали новую — она `03`, потому что `t02`
может встречаться в `movedFrom` и в документах следующего шага.

## 5. `rules` — правила документа, а не настройки человека

| поле | по умолчанию | смысл |
|---|---|---|
| `maxCps` | `25` | символов в секунду; выше — мягкое предупреждение. **Не 17:** это норма читаемости субтитров, а у нас транскрипт живой речи. На восьми реальных сценах порог 17 срабатывал на 52 репликах из 63 — предупреждение, которое горит на всём, человек перестаёт видеть |
| `maxTranslationRatio` | `1.2` | во сколько раз перевод длиннее оригинала. Для дубляжа это важнее CPS: реплика должна уложиться в тот же интервал, а «в полтора раза длиннее» её туда не втиснуть |
| `minDurationMs` | `250` | короче нельзя создать и нельзя дотянуть. Не 400: в живой речи полно реплик вроде «Yeah.» на 340 мс — в первом же реальном проекте таких нашлось две |
| `minGapMs` | `80` | зазор между репликами одной дорожки; меньше — предупреждение |
| `overlapWithinTrack` | `"forbid"` | `forbid` — редактор не даёт наложить реплики одной дорожки; `warn` — даёт с предупреждением |

Между **разными** дорожками наложения нормальны и не ограничиваются никогда: персонажи
говорят одновременно.

**Правила применяются к правкам, а не задним числом.** Реплика, которая уже лежит в документе и
нарушает правило, показывается и правится как обычно — с предупреждением, но без блокировки.
Блокировать разрешено только новое действие человека: нельзя *дотянуть* реплику до длительности
меньше `minDurationMs`, но нельзя и отказаться показать пришедшую такой из обработки. Иначе
инструмент ломается на первом же реальном файле.

Значения по умолчанию выбраны не из головы: они прогнаны через восемь реальных сцен
(`scripts/check-dialog-doc.mjs`). Правило, которое срабатывает почти на каждой реплике, — не
строгость, а шум.

Почему это в документе, а не в настройках инструмента: правила про материал (детская
озвучка — медленнее, реклама — быстрее), они должны ехать вместе с папкой и одинаково
действовать в обеих реализациях. Настройки инструмента — про человека (что показывать,
куда экспортировать) и в документ не попадают.

## 6. Валидация при открытии

Порядок проверок фиксирован, чтобы обе реализации ругались на одно и то же:

1. `format === "dialogDoc"`, иначе — не наш файл;
2. `version` известен — иначе отказ с текстом «документ новее программы» (правило §2.6);
3. пути (§2.7) — любой `..`, ведущий слэш или буква диска → отказ;
4. `tracks[].id` уникальны, `no` уникальны;
5. `cues[].id` уникальны, `trackId` существует в `tracks`;
6. `startMs < endMs`, оба ≥ 0, `endMs <= media.durationMs` (превышение — не отказ, а
   предупреждение: длину могли записать неточно);
7. `tr` содержит только языки из `languages.targets` — лишние **сохраняются**, но не
   показываются (правило §2.5), иначе перевод потеряется при удалении языка из списка;
8. нарушения `rules` — предупреждения, никогда не отказ: файл мог прийти из другого прогона.

Отказ = «не открывать и сказать почему». Молча починить и записать обратно нельзя: это
испортит файл у другой стороны.

## 7. Экспорт: профили

Документ ничего не знает про SRT. Экспортёр — чистая функция «документ → набор файлов»,
профиль выбирается человеком. Файлы кладутся в `exports/<профиль>/…` внутри папки задачи.

| профиль | что делает | состояние |
|---|---|---|
| `srt` | по файлу на дорожку × язык: `exports/srt/es/01-anna.srt`. Нумерация с 1 по возрастанию `startMs`, тайминги `HH:MM:SS,mmm`, пустой текст пропускается | v1 |
| `vtt` | то же, но `WEBVTT` в шапке и `HH:MM:SS.mmm`; `id` реплики пишется идентификатором cue — это даёт обратную связь с документом | v1 |
| `reaper` | проект / разметка для Reaper: дорожка на персонажа, реплики позициями | ⬜ требует отдельного разбора: у Reaper есть и импорт region/marker CSV, и формат проекта `.RPP`; какой из них нужен — проверять на реальном сценарии озвучки |
| `json` | сам документ как есть (для передачи в следующий инструмент) | v1 |

Дорожка `no: 0` («не распознано») в экспорт **не попадает** — пока реплика на ней, она не
приписана никому, и в файле персонажа ей делать нечего. Экспортёр сообщает, сколько реплик
осталось неразобранными.

Правила для всех профилей: оригинальные файлы в папках дорожек (`orig.srt`, `es.srt`) —
**сырьё, их не трогает никто**; повторный экспорт перезаписывает только свою папку профиля;
имя файла строится из `no` и `name` дорожки (`01-anna`), транслитерация и нижний регистр —
на стороне экспортёра, одинаково в обеих реализациях.

## 8. Одновременная правка

**Онлайн (сайт).** Запись условная, по ETag (`ifMatch`). На `412`:

1. перечитать серверную версию;
2. слить по `id`: реплика изменена только у нас → наша; только у них → их; у обоих →
   та, у которой больше `rev`, второй ставится `status: "conflict"`;
3. дорожки — объединение по `id`; при расхождении имени берётся версия из документа с
   большим `revision`;
4. `removed` — объединение;
5. `revision` = max(наш, их) + 1, записать; при повторном `412` — до трёх попыток, дальше
   диалог «сохранить копию `dialog.conflict-<n>.json`».

**Локально (программа).** ETag нет: перед записью сверяются `mtime` и `size` файла с теми,
что были при чтении. Разошлись — тот же алгоритм слияния.

**Незаписанные правки.** Обе реализации держат журнал операций вне документа (IndexedDB на
сайте, файл рядом в программе) и предлагают восстановить после падения. В документ журнал не
попадает.

## 9. Что делает нода графа и чего не делает

Нода `dialogDocBuild` создаёт документ после обработки:

- **нет файла** → создаёт целиком: дорожки по папкам, реплики из `orig.srt` и переводов;
- **файл есть** → только **дописывает**: новые дорожки, новые реплики (по `origin.file` +
  `origin.index`, минус те, что в `removed`);
- существующие реплики, их тексты, тайминги и `status` — **не трогает никогда**;
- `updatedBy` ставит `"node:dialogDocBuild"`, `revision` увеличивает.

Причина такой асимметрии: прогон обработки может случиться после того, как человек уже
поправил документ (добавили язык, перегнали аудио). Перезапись документа нодой уничтожила бы
работу редактора, а отказ от дописывания оставил бы новые дорожки невидимыми.

## 10. Проверка совместимости

Эталон — [dialog.example.json](./dialog.example.json): содержит две дорожки, два языка,
перенесённую реплику (`movedFrom`), удалённую (`removed`), незнакомое поле в реплике (проверка
правила §2.5) и зарезервированные `voice`.

Обе реализации обязаны: открыть его без ошибок, показать 2 дорожки и 4 реплики, сохранить и
дать **побайтово тот же файл**, кроме `revision`, `updatedAt`, `updatedBy` и `producer`.
Незнакомое поле обязано сохраниться. Это дешёвый и жёсткий тест — расхождение форматирования
или потерю поля он ловит сразу.

## 11. Чего не делать

- **Не хранить историю правок в документе.** Файл читается и пишется целиком; история его
  раздувает без предела. Кому нужна история — тому нужен git или отдельный журнал.
- **Не превращать документ в конфиг инструмента.** В нём только то, что описывает материал и
  влияет на результат (§2.8).
- **Не хранить текст удалённых реплик** в `removed` — это не корзина (§4).
- **Не читать экспортированные файлы обратно** (§2.9). Если хочется «подхватить правки из
  SRT» — это импорт нового сырья, он идёт через `origin` и правила §9.
- **Не переиспользовать `no` и `id` дорожек** после удаления.
- **Не писать абсолютные пути** — документ должен переживать переезд папки (§2.7).
- **Не чинить чужой невалидный файл молча** (§6).
