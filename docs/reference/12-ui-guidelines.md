# 12 — Правила построения интерфейса

Как устроен интерфейс, по каким принципам он строится, какими цветами
пользоваться. Документ самодостаточный. Исчерпывающие таблицы всех токенов и
готовые рецепты классов — в `docs/UI_TOKENS.md`; подробные разборы паттернов и
честный список техдолга — в `docs/UI_GUIDE.md`.

---

## 1. Двенадцать правил, которые не обсуждаются

1. **Tailwind utility-first.** Никаких `.css`-файлов, CSS-модулей,
   styled-components, `style={{}}`. Исключение — вычисляемая геометрия:
   координаты контекстного меню, ширины из props.
2. **Цвет — только семантическим токеном**: `bg-card`, `text-muted-foreground`,
   `border-border`, `bg-primary/15`. Хардкод `#hex` / `rgba()` в новом коде
   запрещён.
3. **Тема одна — тёмная.** Токены в `:root`. Вариантов `dark:` не пишем.
4. **Примитивы — из `components/ui/*`.** Свою кнопку, инпут или диалог не пишем.
5. **Каждый компонент принимает `className`** и склеивает его через `cn()`
   последним аргументом — иначе вызывающий не сможет ничего доопределить.
6. **`"use client"` — как можно ниже по дереву.** `layout.tsx` и `page.tsx`
   серверные: авторизация, редиректы, первичные данные.
7. **Именованные экспорты**, `PascalCase` компонент, `kebab-case` файл.
   `export default` — только для `page.tsx` / `layout.tsx`, потому что это
   требование Next.
8. **Варианты компонента — через `cva`**, а не цепочками тернарников в JSX.
9. **Пользовательские строки в `/account` и `/admin` — только через словарь.**
   Строка — это не только текст в JSX: `aria-label`, `title`, `placeholder`,
   тосты, `confirm()` и локаль в `toLocale*` тоже.
10. **Иконки — только `lucide-react`.** `h-4 w-4` в примитивах, `h-5 w-5` в
    навигации.
11. **Ошибка API → `toast.error()`.** Не `alert()`, не молчаливый `return`.
12. **Скролл-контейнеры соблюдают цепочку** `overflow-hidden` →
    `min-h-0 flex-1` → `overflow-y-auto`.

## 2. Пять принципов, из которых выводятся правила

### 2.1. Цвет — это роль, а не оттенок

В коде не бывает «синего». Бывает `primary` (ключевое действие),
`destructive` (удаление), `warning` (пауза), `success` (активно). Правка токена
меняет весь продукт разом — именно за это мы платим запретом на хардкод.

### 2.2. Новых цветов не заводим — набираем прозрачностью

Нужен оттенок посветлее? `bg-primary/10`. Рамка потоньше? `border-border/60`.
Палитра остаётся конечной и внутренне согласованной.

### 2.3. Три зоны, три стилистики, и их не смешивают

Публичный сайт продаёт, рабочая область работает, админка наблюдает. У них разная
плотность, разные шрифты и разные шкалы поверхностей — потому что решают разные
задачи.

### 2.4. Одна кнопка делает одно

Пример из редактора титров: `solo` решает, что звучит, а `wave` — показывать ли
волну. Их не сводят в одну кнопку, хотя визуально соблазнительно: одна кнопка,
делающая две вещи, всегда рано или поздно делает не то, что ждали.

### 2.5. Права рисуют интерфейс, а не наоборот

Кнопка появляется, если её разрешает **и** зона, **и** роль в проекте. Матрица
прав одна и лежит в `lib/project-roles.ts` — том же модуле, по которому проверяют
роуты. Кнопка и проверка на сервере не могут разойтись, потому что читают одно
место.

## 3. Четыре слоя

Зависимости строго сверху вниз: слой не импортирует ничего из слоёв ниже.

| Слой | Что | Где | Правило |
| --- | --- | --- | --- |
| **L0 Токены** | CSS-переменные + маппинг в Tailwind | `app/globals.css`, `tailwind.config.ts` | правка меняет весь продукт |
| **L1 Примитивы** | кнопки, инпуты, диалоги | `components/ui/*` | без бизнес-логики, без `fetch`, без словарей. Только токены и `cva` |
| **L2 Общие блоки** | `EmptyState`, `LoadingBlock`, `SearchInput`, `StatCard`, `SectionHeading`, `*PageHeader` | `components/admin/shared/*`, `components/landing/*`, `*/shell/*` | композиция L1, содержимое через props |
| **L3 Фичи** | `content-grid`, `users-content`, `workspace-*`, `srt/*` | `components/<зона>/…` | знают про API и домен; не переопределяют примитивы, а конфигурируют их |
| **L4 Оболочки** | `layout.tsx`, `page.tsx`, `*Shell` | `app/**`, `components/**/shell` | auth, редиректы, серверные данные, каркас |

**Куда положить новый компонент:**

```
Переиспользуется в 3+ фичах и не знает про домен?  → L2 (…/shared/)
Радиксовый примитив, которого ещё нет?             → L1 (components/ui/, через shadcn CLI)
Иначе                                              → L3, рядом с фичей
```

## 4. Три зоны

| | Публичный сайт | Рабочая область (`/account`) | Админка (`/admin`) |
| --- | --- | --- | --- |
| Каркас | `Header` + контент + `FooterSection` | `WorkspaceShell` | `WorkspaceShell` → `AdminShell` (`max-w-7xl` по центру) |
| Шрифт | Inter (`font-sans`) + Space Grotesk (`font-display`) | IBM Plex Sans | IBM Plex Sans |
| Шкала цветов | `background` / `surface-*` / `card` | **`ws-*`** | `card` / `surface-*` + плитки |
| Плотность | просторно: `section-space` = `py-16 md:py-24 lg:py-32`, `max-w-7xl` | плотно: высоты 34–52px, кегль 11–16px, панели без внешних отступов | средняя: `px-4 py-8 md:px-8 md:py-10` |
| Тон | маркетинговый: градиенты, `spotlight-band`, `premium-card`, reveal-анимации | утилитарный: плоские панели, тонкие бордеры, **никаких анимаций появления** | утилитарный + карточки статистики |
| Язык | английский, строки прямо в JSX | ru/en через `useI18n()` | ru/en через `useAdminI18n()` |
| Скролл | скроллится страница | скроллятся внутренние панели, `h-dvh` фиксирован | скроллится `AdminShell` |

`/login` и `/register` — публичная зона, но верстаются как `Card` по центру, без
маркетингового хедера.

### 5.4. Шкала рабочей области — `ws-*`

Отдельная шкала для рабочего инструмента: плотный тёмно-синий интерфейс, который
**не должен зависеть от палитры публичного сайта**. Значения перенесены один в
один из макета «FF Works — Workspace».

Поверхности:

| Токен | HSL | Где |
| --- | --- | --- |
| `--ws-well` | `220 37% 6%` | самый глубокий: колонка проектов, подложка окна превью |
| `--ws-panel` | `226 26% 9.5%` | панели и области: файловая, IN/OUT, нижняя |
| `--ws-control` | `220 32% 9%` | строки, карточки файлов, инпуты, сегменты |
| `--ws-raised` | `222 30% 12%` | контекстное меню, диалоги |
| `--ws-hover` | `221 31% 13%` | ховер приподнятых элементов, пузырь чата |

Текст — пятиступенчатая нейтральная шкала. **Иерархия задаётся ступенью, а не
размером шрифта:**

| Токен | HSL | Класс | Для чего |
| --- | --- | --- | --- |
| `--ws-text-1` | `217 31% 95%` | `text-ws-1` | основной текст |
| `--ws-text-2` | `220 14% 79%` | `text-ws-2` | вторичный текст, пункты меню |
| `--ws-text-3` | `220 10% 64%` | `text-ws-3` | подписи, неактивные вкладки |
| `--ws-text-4` | `221 9% 42%` | `text-ws-4` | мета файлов, плейсхолдеры, счётчики |
| `--ws-text-5` | `224 13% 33%` | `text-ws-5` | служебные подписи, глифы-разделители, пустые состояния |

Акценты:

| Токен | HSL | Значит |
| --- | --- | --- |
| `--ws-accent` | `211 68% 62%` | заголовки секций, акцент панели **IN** |
| `--ws-action` | `217 89% 53%` | главная кнопка действия |
| `--ws-action-hover` | `217 81% 46%` | её ховер |
| `--ws-select` | `212 74% 52%` | выделение: подсветки, активные сегменты, маркер |
| `--ws-out` | `153 60% 53%` | статус «активен», акцент панели **OUT** |
| `--ws-playhead` | `18 100% 50%` | курсор воспроизведения на таймлинии |

`--ws-playhead` — единственный сигнальный цвет зоны, которому нет пары в шкале
выше. Красный «ошибка» здесь читался бы как поломка, а не как «мы сейчас тут».

### 5.7. Как получать оттенки

| Приём | Пример | Где |
| --- | --- | --- |
| Заливка-подсветка | `bg-primary/10`, `bg-primary/15` | активный пункт меню, иконка в кружке |
| Рамка-акцент | `border-primary/30`, `border-primary/40` | активная карточка, логотип |
| Приглушённая рамка | `border-border/60`, `border-border/80` | панели, разделители |
| Полупрозрачная поверхность | `bg-card/40`, `bg-surface-2/80` | стеклянные блоки |
| Нейтральный оверлей | `bg-white/[0.03]`, `border-white/10`, `hover:bg-white/5` | подсветка на тёмном (это не цвет, а слой) |
| Текст пониженной яркости | `text-foreground/90`, `text-muted-foreground/70` | иерархия текста |
| Инлайн из токена | `shadow-[0_0_0_1px_hsl(var(--primary)/0.25)]` | точечные тени |

### 5.8. Палитра описаний проекта

Отдельная система: в файле `options/description.md` лежит **имя** цвета
(`fg-yellow`, `bg-red-2`), в токен его превращает CSS в `app/globals.css`.

Всё вложено в `.md-palette`, а не глобально: имя `bg-muted` из контракта
совпадает с утилитой Tailwind от токена `--muted`, и без вложенности они спорили
бы за одно правило. Плюс имена палитры не текут в остальной интерфейс.

Подробно — [09 — Инструменты](./09-tools.md#17-палитра-в-файле-имя-цвета-не-код).

Тени:

| Класс | Где |
| --- | --- |

## 8. Layout и контракт скролла

Правило, из-за которого чаще всего ломается вёрстка рабочей области:

```
родитель:  overflow-hidden
ребёнок:   min-h-0 flex-1
внук:      overflow-y-auto
```

Без `min-h-0` флекс-ребёнок не даёт себя сжать, и вместо внутренней прокрутки
уезжает вся страница.

В рабочей области высота фиксирована (`h-dvh`), скроллятся **внутренние
панели**. На публичном сайте и в админке скроллится страница.

Прокрутка оформляется классом `.scrollbar-elegant` — тонкая, полупрозрачная,
на прозрачном треке.

## 9. Адаптивность

Точка разлома в рабочей области — `lg` (1024px):

- `≥ lg` — колонка проектов + рабочая область + нижняя панель;
- `< lg` — одна колонка, `MobileWorkspace`, навигация нижними табами, боковое
  меню выезжает.

Публичный сайт — обычная сетка Tailwind, `sm` / `md` / `lg` / `xl`.

Тянущиеся панели: `ResizeGrip` + `useDragSize`. Ширины сайдбара:
свёрнутая 72px, развёрнутая по умолчанию 248px, минимум развёрнутой 200px, ниже
150px — защёлкивается в свёрнутую.

Сохранение предпочтений в `localStorage`: `ffworks-lang`, `ffworks-ws-density`,
`ffworks-ws-view`.

## 10. Состояния UI

Четыре состояния у любого списка, и все четыре обязательны:

| Состояние | Как показывать |
| --- | --- |
| Загрузка | `Skeleton` (первый рендер) или `LoadingBlock` (обновление внутри страницы) |
| Пусто | `EmptyState`: иконка + заголовок + описание + действие |
| Ошибка | `toast.error()` + разумный фолбэк содержимого |
| Есть данные | собственно список |

Отдельно: **отличать «пусто» от «не готово»**. В статистике `procsTotal = 0`
значит «архив ещё не импортирован», а пустой `volume` — «снимки ещё не
копились», и это не то же самое, что «нет данных». Для этого есть
`components/account/stats-readiness.tsx`.

## 12. Интернационализация

### Три словаря

| Словарь | Хук | Где |
| --- | --- | --- |
| `components/account/i18n.tsx` (~1350 строк) | `useI18n()` | кабинет, оболочка, инструменты |
| `components/admin/admin-dict.ts` (~925 строк) | `useAdminI18n()` | админка |
| `components/markdown/md-dict.ts` (~217 строк) | — | редактор описаний |

Языки: `ru` и `en`. Выбор хранится в `localStorage` под `ffworks-lang`.
Подстановка в шаблон — `tf(t.greeting, { name })` для `"Привет, {name}"`.

`tf` живёт в `i18n.tsx`, а не в `admin-dict.ts`, потому что нужна обеим зонам, а
`components/account` не должен зависеть от `components/admin`. Админский словарь
её реэкспортирует.

### Что считается строкой

Не только текст в JSX: `aria-label`, `title`, `placeholder`, тосты,
`window.prompt`/`confirm`, **и локаль в `toLocaleDateString`**
(`lang === "ru" ? "ru-RU" : "en-US"`).

### Автоматическая проверка

`npm run i18n:check` (`scripts/i18n-check.mjs`) ищет захардкоженные русские
строки в `components/account`, `components/admin`, `app/account`, `app/admin`.
Комментарии не считаются — они в этом проекте по-русски намеренно. Сами словари в
списке исключений.

Проверка появилась не от аккуратности: раздел «Конвейер» был написан целиком на
хардкоде и прошёл ревью, потому что рядом лежали такие же файлы.

⚠️ **Публичный сайт словаря не имеет** — строки лежат в JSX по-английски. Это
известный техдолг.

---

## 13. Иконки, анимация, доступность

**Иконки** — только `lucide-react`. `h-4 w-4` в примитивах, `h-5 w-5` в
навигации, точные размеры (`h-[15px] w-[15px]`) в плотных местах рабочей области.
`optimizePackageImports` в `next.config.mjs` следит, чтобы в чанк не попадала вся
библиотека.

**Анимация**: `tailwindcss-animate` для Radix; `framer-motion` — **только**
`components/landing/motion-reveal.tsx`. В рабочих зонах анимаций появления нет
by design: инструмент не должен «оживать» при каждом обновлении списка.

**Доступность** приходит из Radix: фокус-трапы в диалогах, роли, навигация
клавиатурой, порталы. Своё сверху:
- `aria-label` на иконочных кнопках — через словарь;
- горячие клавиши по `event.code`, а не `event.key` (иначе ломаются на не-латинской
  раскладке);
- `tabular-nums` там, где цифры меняются на месте.

## 14. Чеклист перед коммитом UI-кода

```
□ ни одного #hex / rgba() — только токены
□ ни одного style={{}} кроме вычисляемой геометрии
□ компонент принимает className и склеивает через cn() последним
□ "use client" стоит на самом низком компоненте, которому он нужен
□ все строки /account и /admin — из словаря, ru и en заполнены
□ npm run i18n:check проходит
□ есть все четыре состояния: загрузка, пусто, ошибка, данные
□ ошибка API уходит в toast.error()
□ цепочка скролла соблюдена (overflow-hidden → min-h-0 flex-1 → overflow-y-auto)
□ проверено на < lg
□ кнопки гейтятся правами (can.* / projectCapabilities), а не только скрыты
□ иконки из lucide, размеры по шкале
```

## 15. Антипаттерны

| Не надо | Надо |
| --- | --- |
| `className="text-[#5b9be0]"` | `className="text-ws-accent"` |
| `dark:bg-…` | тема одна, вариантов не пишем |
| своя кнопка на `<button>` с классами | `components/ui/button.tsx` |
| цепочка тернарников для вариантов | `cva` |
| `"use client"` на `page.tsx` | серверная страница + клиентский компонент внутри |
| русская строка в JSX в `/account` | ключ в словаре |
| `alert("Ошибка")` | `toast.error(t.somethingFailed)` |
| `overflow-auto` без `min-h-0` у родителя | полная цепочка скролла |
| `new Date().toLocaleDateString()` без локали | локаль по `lang` |
| скрыть кнопку, но оставить роут открытым | право проверяется и на сервере |
