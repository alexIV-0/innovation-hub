# 09 — Инструменты и работа с документами

Два независимых блока: раздел «Инструменты» с редактором титров и система
markdown-описаний проекта.

# Часть I. Раздел «Инструменты»

Открывается как раздел рабочей области: `/account/projects?tab=tools`. Своё
дерево компонентов, но **внутри того же провайдера** — ему нужны и режим
области, и список проектов (из них выбирается папка задачи).

## 1. Каталог инструментов — в коде

`lib/tools/registry.ts`. Не таблица, и это осознанно: у инструмента есть
интерфейс, поэтому появление нового — всё равно деплой. Таблица добавила бы
второй источник правды и состояние «запись есть, кода нет».

```ts
type ToolDefinition = {
  key: string            // стабильный ключ, попадает в БД, менять нельзя
  kinds: ToolKind[]      // srt | text | video | image | audio | data — из них теги-фильтры
  icon: string           // строковый ключ: модуль читают серверные роуты
  status: "ready" | "soon"
  defaults: Record<string, unknown>
}
```

Имена и описания — не здесь, а в словаре `components/account/i18n.tsx` по ключам
`tool_<key>_name`, `tool_<key>_short`, `tool_<key>_long`.

| Ключ | Виды | Статус | Настройки по умолчанию |
| --- | --- | --- | --- |
| `srt-editor` | srt, video, audio | ✅ ready | `sourceRoot: "OUT"`, `hiddenProjectIds: []`, `autoExport: true`, `autosaveMs: 15000` |
| `voice-over` | audio, srt | ⬜ soon | — |

`status: "soon"` — виден в каталоге, добавить нельзя.

## 2. Экземпляры

Таблица `user_tools`. У экземпляра есть имя, настройки, подключённый источник
(проект + папка задачи), порядок и отметка последнего открытия.

`PATCH /api/account/tools/[id]` **сливает** `settings` и `source` с сохранёнными,
а не заменяет: страница присылает только то, что поменяла, и не должна знать про
остальные ключи.

Удаление мягкое (`deleted_at`).

## 3. Подключение источника

`components/account/tools/source-picker.tsx` — каскадное меню: проект → папка
внутри `settings.sourceRoot` (по умолчанию `OUT`). В `source.label` пишется
человекочитаемая подпись вроде `Sharing Test / OUT / Moneyball`.

Инструмент работает **только онлайн**: папка в хранилище — единственное место,
где лежат файлы, локального кеша нет.

## 4. Область открытого инструмента

`components/account/tools/tool-host.tsx`:

```
tool.toolKey === "srt-editor"  → <SrtEditor tool={tool} />   ← вся область его
иначе                          → общая шапка + сводка документа
```

У инструмента с собственным рабочим местом вся область, с топбаром включительно,
принадлежит ему: топбар несёт счётчики, переключатель языка и экспорт, которые
знает только он.

Ветка «общая шапка + сводка» (`TaskSummary`) на практике недостижима: второй
инструмент в каталоге имеет статус `soon`. Это задел под будущие инструменты.

# Часть II. Редактор титров по дорожкам персонажей

Полная техдокументация — `docs/SRT_EDITOR.md`, формат документа —
`docs/DIALOG_FORMAT.md`, план — `docs/TOOLS_SRT_EDITOR_PLAN.md`. Здесь — карта.

## 5. Что это

Редактор субтитров, где каждая дорожка — персонаж. Читает папку задачи из `OUT`,
правит документ `dialog.json`, экспортирует SRT/VTT.

## 6. Карта кода

### Модель — `lib/tools/srt/` (без React, чистые функции)

| Модуль | Что |
| --- | --- |
| `dialog-doc.ts` | тип документа, разбор с валидацией, **все** операции: правка текста и перевода, сдвиг таймингов, перенос между дорожками, разрез, объединение, добавление и удаление реплик, языков, дорожек |
| `serialize.ts` | канонический вид для записи и сравнения; `stampForSave` проставляет ревизию, время и автора |

| `export.ts` | SRT, SRT с BOM, VTT |
| `timecode.ts` | форматирование и разбор таймкодов |
| `timeline.ts` | масштаб (пикселей на секунду), тики линейки, привязка (snap) |
| `peaks.ts` | разбор `*.peaks.json` и сведение к столбикам волны |

Всё чистое: файл целиком переезжает в локальный редактор программы, поэтому ни

## 7. Документ `dialog.json`

```ts
DialogDoc = {
  format: "dialogDoc", version: 1,
  id, revision, updatedAt, updatedBy, producer,
  media:     { video, mix, peaks, durationMs, fps },
  languages: { original, targets[] },
  rules:     DialogRules,
  tracks:    Track[],
  cues:      Cue[],
  removed:   { id, at }[],
  extra?:    {…}
}
```

| Сущность | Ключевое |
| --- | --- |
| `Cue` | `trackId`, `startMs`/`endMs`, `text`, переводы `tr` по коду языка, `status` (`auto`/`edited`/`approved`/`conflict`), `rev`, `origin`, `extra` |
| `Track` | `no`, `name`, `color`, свой `audio` и свои `peaks` (может не быть), `diar`, `voice` |
| `DialogRules` | `maxCps: 25`, `maxTranslationRatio: 1.2`, `minDurationMs: 250`, `minGapMs: 80`, `overlapWithinTrack: "forbid"` |

**Поле `extra` есть у документа, дорожки и реплики.** В него складывается всё,
чего эта реализация не знает, и записывается обратно как есть — чтобы вторая
реализация (локальный редактор) не теряла свои поля.

Порядок реплик в файле: `startMs`, затем `trackId`, затем `id` — детерминированно,
чтобы диффы файла были осмысленными.

### Отказ вместо молчаливой починки

`parseDialogDoc` при проблеме **отказывается открыть** документ. Причины
(`DocError`): не наш файл, версия новее, плохой путь, дубль дорожки, дубль
реплики, неизвестная дорожка, некорректный интервал, отсутствующее поле.

Документ общий с программой, и «поправили и записали обратно» испортило бы файл
у второй стороны. Текст ошибки подбирает интерфейс — модель возвращает только
повод.

`DOC_VERSION = 1` — единственная поддерживаемая major-версия.

### Цвета дорожек

`TRACK_COLORS` — цвета по умолчанию, когда конвейер их не проставил.
`TRACK_PALETTE` (12 цветов) — из чего человек выбирает руками.

Не пипетка и не колесо: цвет здесь — метка персонажа, и её задача одна —
отличаться от соседней. Свободный выбор на тёмном фоне даёт нечитаемые оттенки,
поэтому набор фиксированный и проверенный на этом фоне.

## 8. Правки и отмена

Все операции модели чистые: принимают документ, возвращают новый. Поэтому
**undo — это стек снимков ссылок**, а не обратные действия. Одно движение мыши
(протяжка клипа) = один шаг отмены: `setTiming` принимает признак `gesture`.

## 9. Инструменты таймлинии и горячие клавиши

| Инструмент | Клавиша по умолчанию |
| --- | --- |
| выделение (`select`) | `V` |
| создание (`create`) | `C` |
| разрез (`razor`) | `B` |
| перенос (`shift`) | `M` |
| объединение (`merge`) | `J` |
| play/pause | `Space` |
| основная волна (`mainWave`) | `W` |

Клавиши хранятся **кодом физической кнопки** (`KeyB`), а не набранным символом:
`event.key` зависит от раскладки — на русской та же кнопка даёт «и», и привязка к
букве перестаёт работать, пока не переключишь язык. Переназначаются в настройках.

## 10. Флаги дорожки — это вид, а не документ

`TrackFlags = { solo, mute, shy, wave }` живут вне документа.

Что звучит, решает `solo`; `wave` — показывать волну этой дорожки или нет. Волна
на звук не влияет и наоборот: иначе одна кнопка делала бы две разные вещи.

Звук: звучат дорожки с `solo`, не `mute`, со включённым своим звуком и
существующим файлом. Пусто — звучит основная дорожка (звук видео). Как только
кто-то включил `solo`, звук видео заглушается.

Волна дорожки: своя, если есть; иначе общая, приглушённо.

## 11. Автосохранение

`use-autosave.ts`:

| Параметр | Значение | Почему |
| --- | --- | --- |
| Затишье | 1200 мс | человек ждёт, что правка сохранится сразу. Задержка нужна только чтобы протяжка клипа и набор текста уехали одной записью, а не шестьюдесятью |
| Максимум ожидания | 8000 мс | дольше не тянем даже при непрерывной работе |

Состояния: `clean` → `pending` → `saving` → `saved` | `merged` | `error`.

## 12. Запись документа: `PUT /api/account/tools/[id]/document`

**Читает-сливает-пишет на сервере**, а не тремя запросами из браузера, и по
одной причине: между чтением и записью не должно быть окна, в которое влезет
вторая вкладка.

```
PUT { doc, baseRevision }
  → находим экземпляр инструмента, из него projectId + folderPath
  → requireProjectAccess(projectId, userId, "editor")
  → parseDialogDoc(doc)         ← испорченный документ до хранилища не доходит
  → читаем dialog.json из папки
  → ревизия в папке совпадает с baseRevision?
        да  → пишем поверх
        нет → mergeDialogDocs(наш, их)  и пишем результат
  → stampForSave: revision, updatedAt, updatedBy, producer
  → writeNotifyUpload — ТОТ ЖЕ путь записи, что у остальных файлов проекта
```

Последнее важно: журнал изменений и курсор синхронизации остаются верными,
документ виден в дереве и уезжает клиентам через `delta`.

### Правила слияния

| Ситуация | Решение |
| --- | --- |
| Реплика только у одной стороны | берётся как есть, если её нет в `removed` у другой |
| Реплика у обеих | выигрывает та, у которой больше `rev` |
| `rev` равны, содержимое разное | берётся **наша** (мы правим прямо сейчас), выжившая помечается `status: "conflict"` — человек должен увидеть, что чужая правка не пропала бесследно, а была перекрыта |
| Дорожки | объединение по `id`; имя и цвет — из документа с большей `revision` |
| `removed` | объединение; всё, что в нём, выбрасывается из реплик |
| `revision` результата | `max(наш, их) + 1` |

Побеждать «последнему записавшему» нельзя — это молча стирает чужую работу.

Тот же алгоритм переезжает в локальный редактор программы, где применяется по
`mtime` + `size` вместо ETag.

## 13. Экспорт

`SRT`, `SRT с BOM` (для плееров, которые иначе не читают UTF-8), `VTT`.
`settings.autoExport` — экспортировать при каждом сохранении документа.

## 14. Что нужно от программы обработки

Папка задачи в `OUT` (контракт — `docs/SRT_EDITOR.md`, часть II):

```
OUT/{задача}/
  dialog.json          ← документ
  source.mp4           ← видео
  mix.peaks.json       ← общая волна
  {no}/orig.srt        ← сырьё титров дорожки
  {no}/{lang}.srt      ← переводы
  {no}/audio.wav       ← стем дорожки (необязательно)
  {no}/audio.peaks.json
  exports/             ← результаты экспорта
```

Со стороны программы нужны две новые ноды: `audioPeaks` (пики для таймлинии) и
`dialogDocBuild` (сборка документа). Оба помечены ⬜ в плане; реальные данные
приходят из конвейера Cast Analyzer Next
(`scripts/import-castanalyzer.mjs` конвертирует его проекты в задачи).

# Часть III. Описание проекта (markdown)

Формат — `docs/DESCRIPTION_FORMAT.md`, эталон — `docs/description.example.md`.

## 15. Что это

`options/description.md` в папке проекта — развёрнутый бриф: текст с цветными
выделениями, картинки, таблицы, блок-схемы. Отдельный файл, а не поле в
`options.json`: тот принадлежит редактору нод, его формат задаёт десктоп.
Короткая подпись остаётся в `projects.description` — она нужна на карточке в
списке, а ходить за ней в R2 на каждый рендер нельзя.

Пишет команда (админский «Конвейер» или программа), читает клиент.

## 16. Конвейер рендеринга

```
markdown → remark-parse → remark-gfm → remark-rehype(allowDangerousHtml)
         → rehype-raw → rehype-sanitize(descriptionSanitizeSchema) → HTML
```

**Порядок критичен.** Если санитайз встанет раньше `rehype-raw`, разметка либо не
разберётся, либо пролезет непроверенной. Санитайз обязателен именно **на
рендере**, а не только при сохранении: файл приходит из программы и мог быть
отредактирован кем угодно — доверенным содержимым он не является ни для одной из
сторон.

Один и тот же конвейер в трёх местах: просмотрщик
(`components/markdown/markdown-view.tsx`, через `react-markdown`), загрузка в
редактор (`lib/markdown/markdown-to-html.ts`, через `hast-util-to-html`), превью
внутри редактора. Одним компонентом рисуется и панель, и модалка, и превью —
иначе «как вижу» и «как сохранится» разъезжались бы.

## 17. Палитра: в файле имя цвета, не код

```html
<span class="fg-yellow">текст</span>
<span class="fg-red bg-yellow">текст</span>
```

В файле лежит **имя** цвета; в токен темы его превращает CSS в
`app/globals.css`. Ступень насыщенности (`-2`, `-3`) — прозрачность того же
токена. Новых цветов не заводится.

Всё вложено в `.md-palette`, а не лежит глобально, по двум причинам: имя
`bg-muted` из контракта совпадает с утилитой Tailwind от токена `--muted`, и без
вложенности они спорили бы за одно правило; плюс имена палитры не текут в
остальной интерфейс. Тот же класс висит на сетке образцов в тулбаре — цвет
кнопки берётся оттуда же, откуда цвет текста, и не может разъехаться.

Доступно: `blue`, `green`, `orange`, `red`, `yellow`, `teal`, `purple`, `cyan`,
`pink`, `muted` (по три ступени каждый) и серая шкала `gray-0`…`gray-5`.
Заливка (`bg-*`) не меняет цвет текста: `fg-*` и `bg-*` могут стоять на одном
span.

Плюс `align-left|center|right|justify` и `indent` (красная строка).

## 18. Типографика

`.md-body` в `app/globals.css`. `@tailwindcss/typography` в проекте нет, и он всё
равно не знает про классы `fg-*` / `align-*` / `indent`.

Две переменные задают всё остальное:
- `--md-font-size` (14px) — базовый кегль, вся типографика считается от него в
  `em`, поэтому переключатель размера в модалке меняет одну переменную;
- `--md-measure` (820px) — ширина колонки текста; контейнер при этом тянется.

Правила адаптивности, без которых описание ломает страницу (жёстких размеров в
файле нет by design):
- `overflow-wrap: anywhere` — длинный путь или URL иначе распирает layout;
- широкая таблица прокручивается внутри `.md-table-wrap` — обёртку из markdown
  задать нельзя, её ставит рендерер;
- `pre { overflow-x: auto }`;
- `img { max-width: 100%; height: auto }`.

## 19. Два редактора, одна панель кнопок

| Режим | Модуль API | Что внутри |
| --- | --- | --- |
| Текстом | `lib/markdown/editor-api.ts` | поверх чистых функций `markdown-commands.ts` |
| «Как выглядит» | `lib/markdown/tiptap-api.ts` | Tiptap, схема расширений повторяет закрытый список HTML из контракта |

Тулбар (`components/markdown/markdown-toolbar.tsx`) один и не знает ни про
синтаксис markdown, ни про имена классов палитры — за интерфейсом `EditorApi`
стоят две реализации. Так же устроено в программе.

## 20. Блок-схемы

Фенсы с языком `mermaid` рендерит `components/markdown/mermaid-block.tsx`. Библиотека
импортируется **динамически**. Незнакомый язык фенса обязан выглядеть обычным
блоком кода, а не ошибкой: диаграмма получает свой контейнер `.md-mermaid`, всё
остальное остаётся `<pre>`.

Цвета диаграммы задаются через `mermaid.initialize` готовыми CSS-значениями,
считанными из токенов темы, — потому что mermaid не понимает `hsl(var(--…))`.

## 21. Картинки внутри файла

Картинки лежат в самом markdown как `data:`-URI. `next/image` для `data:` не
годится, поэтому просмотрщик рисует обычный `<img>`. Подготовка (сжатие,
масштабирование перед вставкой) — `lib/markdown/prepare-image.ts`.

Картинка без `src` после санитайза — это вырезанный мусор, а не картинка, и не
рисуется вовсе.
