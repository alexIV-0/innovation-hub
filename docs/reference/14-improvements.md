## 1. Две поверхности одного storage API разошлись

**Это не стилистическая претензия — это уже случившееся расхождение.**

Одни и те же операции реализованы дважды: как route handler в
`app/api/storage/v1/*/route.ts` и как экшен в
`lib/machine-api/actions/storage-write.ts`. Схема, проверка доступа, вызов
доменной функции и разбор ошибок скопированы построчно.

### Доказательство расхождения

| Операция | Route | Action | Разница |
| --- | --- | --- | --- |
| `mkdir` | [`route.ts:12-19`](../../app/api/storage/v1/mkdir/route.ts#L12-L19) принимает `ensurePath` и создаёт всю цепочку родителей через `writeEnsureFolderPath` | `mkdirAction` этого поля **не знает** | машина не может создать вложенный путь одним вызовом, десктоп по REST — может |
| `rename` | схема без `.refine()`, проверка «нужно name или folderPath» сделана **вручную после** парсинга ([`route.ts:41-46`](../../app/api/storage/v1/rename/route.ts#L41-L46)) | `renameAction` держит `.refine()` в схеме | текст и форма ошибки различаются |

Само наличие расхождения — предсказанное последствие. В `queue-endpoint.ts`
автор написал прямо: *«одна логика, тонкие обёртки, иначе поверхности
разъедутся»*. В этих семи операциях так не сделали, и они разъехались.

### Где правильный образец уже есть

| Домен | Общий модуль |
| --- | --- |
| Очередь задач | `lib/pipeline/queue-endpoint.ts` |
| Общие словари | `lib/settings-endpoint.ts` |
| Проекты | `lib/storage/project-mutations.ts` + `project-catalog.ts` |
| Multipart | `lib/storage/multipart.ts` |
| Корзина, копирование, работы | `lib/storage/{trash,copy,jobs}.ts` |

Осталось семь операций без общего модуля: `presign` (116 строк роута), `notify`
(86), `mkdir` (91), `rename` (83), `object` (66), `reindex` (44), `sidecars`
(181). Итого ~670 строк роутов против 483 строк экшенов.

### Что сделать

Завести `lib/storage/*-endpoint.ts` по образцу `settings-endpoint.ts`: схема
одна, обработчик один, возвращает данные или `{error, status}`. Роут остаётся
тонким: авторизоваться, разобрать тело, вызвать. Экшен — то же самое через
`defineAction`.

Отдельно: **сначала сверить поведение** пары `mkdir`/`rename` и решить, какая
версия правильная. Скорее всего `ensurePath` нужен обеим — тогда это ещё и
починка возможности для машин.

## 2. `videos` и `ideas` — две копии одной сущности

`VideoRecord` и `IdeaRecord` в `lib/domain-types.ts` — **побайтово одинаковые
типы**. Таблицы `videos` и `ideas` в `db/schema.sql` отличаются только именем.

Продублировано:

| Слой | Файлы |
| --- | --- |
| Тип | `VideoRecord` / `IdeaRecord` |
| Таблица | `videos` / `ideas` (одинаковые поля, одинаковые GIN-индексы по `tags`) |
| Репозиторий | `lib/repositories/videos.ts` (372) / `ideas.ts` (181) — общий `mapRow`, нормализация тегов, `reorder` |
| Схемы | `videoCreateSchema` / `ideaCreateSchema` в `lib/admin-schemas.ts` |
| Роуты | 4 файла на видео / 3 на идеи (803 строки суммарно) |
| UI | `admin-video-card.tsx` / `admin-idea-card.tsx`, а `content-content.tsx` их **всё равно склеивает** в один список `ContentItem { kind, data }` |

Показательно, что интерфейс уже мыслит их одной сущностью с полем-дискриминатором
`kind` — а данные и API нет.

### Что расходится прямо сейчас

| | видео | идеи |
| --- | --- | --- |
| `revalidateTag("published-videos")` при мутации | ✅ есть | ❌ **нет** |
| `reorder-bulk` (порядок после drag) | ✅ есть | ❌ нет, только пошаговый |

То есть правка идеи не сбрасывает кеш витрины, а порядок идей нельзя задать
перетаскиванием. Оба следствия — прямо из дублирования.

### Что сделать

Один из двух путей:

**A. Объединить в `content_items` с колонкой `kind`.** Правильнее, но нужна
миграция данных и переписывание роутов. Даёт бесплатно: единый кеш-тег,
`reorder-bulk` для обоих, один тип, одна карточка.

**B. Оставить таблицы, объединить код.** Дешевле: генератор репозитория
`createContentRepository(table)`, один набор роутов с параметром `kind`,
одна карточка. Расхождения выше исчезают, миграции нет.

Начинать стоит с B — она снимает наблюдаемые баги, не трогая данные.

## 5. Политики загрузки

`lib/s3-upload-policy.ts` и `lib/project-upload-policy.ts` содержат почти
идентичные функции `resolveUploadContentType` / `resolveProjectContentType` —
включая **одну и ту же таблицу «расширение → MIME»**, скопированную построчно
(`.jpg`, `.png`, `.webp`, `.gif`, `.mp4`, `.webm`, `.mov`).

`lib/public-upload-policy.ts` при этом сделан правильно: реэкспортирует общие
функции и добавляет только свои лимиты. Это и есть образец.

**Что сделать:** одна таблица расширений в общем модуле, две политики поверх
неё — каждая со своим набором разрешённых MIME.

Заодно: добавление типа файла сейчас требует правки в двух местах, и легко
получить состояние «в проект грузится, в витрину нет» по недосмотру, а не по
решению.

## 7. Cron-роуты

Обязанности перепутаны, а общая обвязка скопирована.

| Роут | Что делает |
| --- | --- |
| `/api/cron/storage-jobs` | разбирает работы **+ чистит корзину** |
| `/api/cron/storage-purge` | **чистит корзину** + снимок + импорт архива + экспорт |

Чистка корзины — в обоих. Функция `authorize` (`CRON_SECRET` или сессия админа)
скопирована в оба файла.

Плюс `storage-purge` дублирует всё, что делает часовой тик
`lib/statistics/stats-loop.ts`. Это заявлено в комментариях как «второй, ручной
вход», и решение правильное — но тогда роут должен вызывать **ту же функцию
тика**, а не свою копию последовательности.

**Что сделать:** вынести `authorizeCron(request)` в общий модуль; развести
обязанности («работы», «чистка», «статистика») или свести в один роут с
параметром; статистику вызывать одной функцией, общей с тиком.

## 8. Envelope-обвязка роутов

В 32 route-файлах повторяется один и тот же блок:

```ts
let body: unknown
try { body = await request.json() } catch {
  return NextResponse.json({ message: "Invalid JSON." }, { status: 400 })
}
const parsed = schema.safeParse(body)
if (!parsed.success) {
  return NextResponse.json(
    { message: parsed.error.issues[0]?.message ?? "Invalid input." },
    { status: 400 },
  )
}
```

Это не опасно — но 32 копии значат, что формат ошибки валидации меняется в 32
местах, и уже сейчас он не везде одинаковый: часть роутов отдаёт
`{message, errors: parsed.error.flatten()}`, часть только первый `issue`.

**Что сделать:** `parseJsonBody(request, schema)` → `{data}` | `NextResponse`,
ровно в той же идиоме, что уже используют гварды доступа. Правка механическая.

## 9. `typescript.ignoreBuildErrors: true`

`next.config.mjs` отключает падение сборки на ошибках типов, при том что
`tsconfig.json` стоит в `strict: true`.

Практический смысл настройки: типы в этом проекте — документация, а не гарантия.
Например, обвязка вроде `if (auth instanceof NextResponse) return auth` спасает
только пока её пишут руками — компилятор про пропущенную проверку не скажет,
если сборка всё равно зелёная.

**Что сделать:** запустить `npx tsc --noEmit`, оценить число ошибок. Дальше —
либо починить и снять флаг, либо снять флаг и добавить в скрипты
`typecheck` отдельным шагом. Оценить объём заранее нельзя, поэтому пункт стоит
не в начале списка.

Рядом: `npm run lint` вызывает `next lint`, а конфигурации ESLint в репозитории
нет; тестов нет вообще. Автопроверок в проекте две — `i18n:check` и `md:check`,
и обе запускаются вручную. Минимальный CI, дёргающий три команды, стоит дешевле
любого из пунктов выше.

незаполненный шаблон на живом сайте.

## 11. Заглушки, которые выглядят рабочими

`/api/feature-suggestions` и `/api/video-orders` валидируют, проверяют honeypot,
считают rate limit — и отдают **503** с `TODO(yougile)`.

отказ на саму заявку, а объекты остаются в бакете, и снять их нечем — строки
каталога у них нет.

**Что сделать (по возрастанию цены):**
1. отключить форму в UI или показать честное «пока не работает» — чтобы файлы не

## 13. Состояние в памяти процесса

Три места привязывают приложение к одному инстансу:

| Что | Где | Последствие второго инстанса |
| --- | --- | --- |
| Rate limit | `lib/rate-limit.ts` — `Map` в модуле | лимит станет N-кратным |
| Флаги «цикл запущен» | `runner.ts`, `stats-loop.ts`, `chat-push-poller.ts` | циклы задублируются. Операции идемпотентны, но нагрузка на YouGile (лимит 50 req/min) и R2 удвоится |
| Кеш «чата больше нет» | `lib/project-chat-sync.ts` — `Set` | не критично |

Сейчас это **не проблема**: `ecosystem.config.json` держит один инстанс
осознанно. Пункт нужен как ответ на вопрос «что чинить, если понадобится
горизонтально масштабироваться»: rate limit → Redis/KV, флаги циклов →
advisory-локи Postgres.
