# Озвучка реплик — техническая документация

**Что это.** Инструмент в кабинете (`/account/projects?tab=tools`), который берёт ту же
папку задачи и тот же документ `dialog.json`, что редактор титров, и озвучивает реплики
синтезом: по реплике или всё подряд, на любом языке — включая перезапись оригинала.
Готовый звук ложится клипами на таймлинию, его слышно вместе с кадром, можно подстроить
и выгрузить. Работает **только онлайн**.

**Границы.** Инструмент не правит титры (это соседний инструмент, и вторая точка правды
на один текст была бы источником расхождений), не переводит, не отделяет голоса по
персонажам и не рендерит видео. Синтеза у него своего тоже нет: сейчас на его месте
заглушка, отдающая настоящий WAV ([Часть III](#часть-iii-как-подключить-настоящего-провайдера)).

**Соседние документы.**

| документ | о чём |
| --- | --- |
| [DIALOG_FORMAT.md](./DIALOG_FORMAT.md) | **нормативный** контракт `dialog.json`, включая поля озвучки. При расхождении прав он |
| [SRT_EDITOR.md](./SRT_EDITOR.md) | первый инструмент над тем же документом: чтение папки, сохранение, контракт папки задачи в `OUT` |
| [TOOLS_VOICEOVER_PLAN.md](./TOOLS_VOICEOVER_PLAN.md) | проектные решения, статус пунктов, что ещё не сделано |
| [TOOLS_DEV_GUIDE.md](./TOOLS_DEV_GUIDE.md) | как вообще делается инструмент раздела |

Дата сверки с кодом: **2026-08-27** (ветка `UI_dev`).

# Часть I. Как устроен инструмент

## 1.1. Карта кода

Инструмент писался вторым, и его главная особенность — сколько он **не** написал:
чтение папки, автосохранение, часы, превью, полотно таймлинии, линейка, волна, окно
настроек и справка взяты из каркаса как есть.

**Своя чистая логика — [lib/tools/](../lib/tools/), без React и без DOM.**

| файл | что внутри |
| --- | --- |
| `dialog/voice.ts` | вся модель озвучки: разметка, тейки, выбор, подстройка, «вписать в реплику», номера файлов, `pruneTakes` |
| `voice/export.ts` | что именно выгружается: какие тейки, в какие файлы, под какими именами |
| `voice/render.ts` | сведение звука через Web Audio — единственный модуль инструмента, которому нужен браузер |
| `voice/wav.ts` | кодировщик WAV 16 бит моно (44 байта заголовка, без зависимостей) |
| `voice/stub.ts` | поддельный синтез: настоящий звук, детерминированный по `seed` |

Модель озвучки лежит **вместе с документом** (`lib/tools/dialog/`), а не отдельной
сущностью: это тот же файл, и озвучка — ещё один слой поверх реплик.

**Интерфейс — [components/account/tools/voice/](../components/account/tools/voice/).**

| файл | что внутри |
| --- | --- |
| `voice-editor.tsx` | корень: топбар, раскладка зон, клавиши, сборка состояния, приём готовых тейков |
| `voice-context.tsx` | всё состояние одним объектом для зон |
| `prefs.ts` | раскладка клавиш, состав настроек вида, `matchesHotkey` |
| `cue-list.tsx` | зона 3: титр (только чтение) ↔ текст для синтеза ↔ состояние озвучки |
| `timeline-pane.tsx` | зона 4: титры фоном, клипы тейков поверх |
| `preview-pane.tsx` | зона 2: кадр, титры поверх, звучат тейки |
| `use-generation.ts` | очередь генерации |
| `export-dialog.tsx`, `settings-dialog.tsx`, `help-dialog.tsx` | окна |

**Сервер — [app/api/account/tools/[id]/voice/generate/route.ts](../app/api/account/tools/%5Bid%5D/voice/generate/route.ts):**
единственный роут инструмента. Запись документа — общая, через
`PUT /api/account/tools/[id]/document`.

## 1.2. Что читается из папки

Ровно то же, что у редактора титров, тем же `useTaskFolder`: дерево через
`GET /api/storage/v1/tree`, документ через `/api/projects/[id]/drive/files/[fileId]`,
видео и волны — подписанными ссылками прямо в R2. Плюс своё:

| что | откуда | если нет |
| --- | --- | --- |
| файлы тейков и их волны | `{NN}/voice/…` в папке задачи, подписанные ссылки по требованию | клип рисуется без волны, звук не играет |
| пример голоса дорожки | `tracks[].voice.sample`, иначе `tracks[].audio` (стем из оригинала) | у синтеза нет образца — вопрос к провайдеру, не к инструменту |

Подписывание ссылок разведено на два хука сознательно: `takeUrl` держит только то, что
сейчас звучит (выбранные тейки текущего языка), а экспорту нужны и прошлые языки, и
невыбранные дорожки — он просит ссылку в момент выгрузки (`signTake`).

## 1.3. Модель озвучки в документе

Три поля, добавленные к документу (полное описание — §3
[TOOLS_VOICEOVER_PLAN.md](./TOOLS_VOICEOVER_PLAN.md), нормативно —
[DIALOG_FORMAT.md](./DIALOG_FORMAT.md)):

```
tracks[].voice = { provider, voiceId, params, sample }   // чем озвучивать персонажа
cues[].voice   = { markup: { [lang]: text }, takes: [] } // что и чем озвучено
```

Тейк:

| поле | смысл |
| --- | --- |
| `lang` | язык тейка. У реплики свой набор тейков на каждый язык |
| `file`, `peaks` | относительные пути в папке задачи |
| `durationMs` | сколько звучит файл как он есть |
| `selected` | выбранный тейк — **один на язык** |
| `offsetMs`, `rate`, `gainDb` | подстройка: сдвиг, скорость, громкость |
| `source` | текст, который отдали синтезу — по нему видно, что тейк устарел |
| `provider`, `voiceId`, `createdAt` | чем и когда сделан |

Три правила, из которых выводится всё остальное:

1. **Тейк привязан к языку.** Испанский и французский у одной реплики — разные наборы.
2. **Подстройка непортящая.** `offsetMs`, `rate`, `gainDb` — параметры, файл на диске не
   меняется, применяют их превью и рендер. Иначе каждое движение ползунка громкости
   означало бы перезапись файла в хранилище.
3. **Начало важно, конец — нет.** Тейк начинается в `startMs + offsetMs` и длится столько,
   сколько длится звук. Перекрытие тейков внутри дорожки — норма, и
   `rules.overlapWithinTrack` к ним не относится: оно про читаемость титров.

**Разметка.** `markup[lang]` — то, что уйдёт в синтез. Пусто — синтезируется сам титр,
поэтому дублировать титр в разметку заранее не нужно: правка титра сразу отражается на
озвучке. В интерфейсе поле показывает **текст, а не подсказку**: пока своей разметки нет,
там копия титра — её и правят, вписывая теги. Текст, совпавший с титром, разметкой не
считается: одно случайное нажатие не должно отцеплять реплику от титра навсегда.

**Устаревший тейк** — `take.source !== synthText(doc, cue, lang)`. Сравнение по тексту, а
не по времени правки: титр могли поправить и вернуть как было.

## 1.4. Язык

Всегда конкретный код: первый перевод, а если переводов нет — оригинал. Озвучить оригинал
можно (перезапись), «ничего» — нельзя, поэтому `null` здесь не бывает, в отличие от
редактора титров, где `null` означает «показываем оригинал».

Смена языка обнуляет очередь генерации: то, что в ней стояло, относилось к другому
материалу.

## 1.5. Генерация

**Очередь живёт в памяти вкладки** ([use-generation.ts](../components/account/tools/voice/use-generation.ts)).
Состояния — `idle` / `queued` / `running` / `failed`, и в документ они не пишутся: это
состояние интерфейса, а не результат работы (правило §2.8 контракта формата). Результат —
это уже запись в документе, и дальше он идёт обычным путём: автосохранение, слияние,
отмена.

Одновременных запросов немного, по умолчанию два (`settings.concurrency`, настраивается):
провайдер внешний и с ограничениями по частоте, двадцать параллельных вернут ошибки
вместо звука.

Перед каждым запросом вызывается `beforeRequest` → `save.flush()`. Без этого «поправил
разметку и нажал озвучить» синтезировало бы текст до правки: роут читает документ **из
папки**, а правка уходит туда автосохранением с задержкой.

`cancelAll` отменяет только то, что ещё не ушло: начатое дорабатывает, байты уже пишутся.

**Роут генерации** делает пять вещей и ни одной лишней:

1. проверяет сессию, экземпляр, источник и права (`editor`);
2. читает документ из папки — синтезировать надо то, что сохранено, иначе тейк не
   совпадёт с тем, что увидит второй человек;
3. синтезирует (сейчас — заглушка), считает пики;
4. кладёт `*.wav` и `*.peaks.json` в папку задачи через `writeNotifyUpload` с
   `isUploader: false`;
5. возвращает **описание тейка**, а в документ его вписывает клиент.

Пятый пункт — не мелочь: документом владеет клиент, и второй писатель здесь создал бы
гонку с автосохранением.

## 1.6. Подстройка тейка

Три числа, и больше ничего: `offsetMs`, `rate`, `gainDb`. Границы —
`rate ∈ [0.5, 2]`, `gainDb ∈ [-24, +12]`, приводятся в модели, а не в интерфейсе.

| жест | что меняет |
| --- | --- |
| тянуть клип | `offsetMs`; начало не уезжает левее нуля таймлинии |
| ручка у правого края клипа (8 px) | `rate` |
| Alt + колесо над клипом | `gainDb` |
| «вписать в реплику» (`F`) | подбирает `rate`, чтобы тейк кончился вместе с репликой |

`fitTakeToCue` по кнопке работает в обе стороны — «в размер» значит ровно в размер.
Автоматическое вписывание после генерации спрашивает разрешение у настроек, и это **две
независимые половины**: `autoFitShrink` (ужать вылезшее) и `autoFitStretch` (растянуть
короткое). Обе по умолчанию выключены: первое, что человек слышит, должно быть
результатом провайдера, а не нашей подгонки. Настройки читаются в момент прихода тейка, а
не когда заводилась очередь.

## 1.7. Что звучит

По умолчанию — **сгенерированное**, звук видео заглушён: человек проверяет дубляж, а не
оригинал. Оригинал — по кнопке (`O`), чтобы сравнить.

Набор звучащих тейков: выбранные тейки видимых дорожек текущего языка; `solo` сужает,
`mute` убирает. Играются они через `<audio>` с поправкой по дрейфу
([shared/track-audio.tsx](../components/account/tools/shared/track-audio.tsx)): порог 40 мс
— половина слога, меньше человек не слышит, больше уже эхо. Часы одни — плеер превью.

Подпись под превью обязана совпадать с тем, что слышно, включая случай «тишина, потому
что на этом языке ещё ничего не озвучено».

## 1.8. Правки, отмена, сохранение

Всё общее с редактором титров: `useUndoableDoc` (история снимками, глубина 100,
`gesture` склеивает одно движение), `useAutosave` (затишье 1.2 с, потолок 8 с, слияние с
чужой версией, предупреждение при уходе со страницы), запись через
`PUT /api/account/tools/[id]/document`.

Одна деталь модели: любая правка озвучки поднимает `cue.rev`. Озвучка — такая же правка
реплики, и слияние с чужой версией должно видеть, что наша сторона новее.

## 1.9. Экспорт

Решения о том, что выгружать, — чистые ([voice/export.ts](../lib/tools/voice/export.ts)),
сведение звука — в браузере ([voice/render.ts](../lib/tools/voice/render.ts)).

**План.** Языки переключателями, дорожки чекбоксами, раскладка — `single` (сведённый
дубляж одним файлом) или `per-track` (по файлу на персонажа). Дальше правило раздела:
один файл отдаётся файлом, несколько — архивом, и внутри архива язык становится папкой.
В выгрузку идут **только выбранные** тейки: прежние версии — история, а не результат, и
сложить их в один файл значило бы наложить несколько прочтений одной реплики.

**Сведение.** `OfflineAudioContext`: каждый тейк скачивается по подписанной ссылке,
декодируется, получает `gainDb` и `rate` и ставится в `startMs + offsetMs`. Хвост в
секунду — последний тейк может кончиться позже материала. Сначала собирается всё, потом
файл уходит в браузер: отдавать по одному значит оставить человека с половиной архива,
если на третьем оборвётся сеть.

**Честная оговорка про скорость.** `playbackRate` у Web Audio — пересэмплирование, оно
меняет высоту голоса. В превью браузер высоту сохраняет (`preservesPitch` у `<audio>`),
поэтому ускоренный тейк в файле звучит выше, чем в редакторе. Окно экспорта об этом
предупреждает, когда в выгрузке есть тейк с `rate ≠ 1`. Закрывается это растяжением по
времени или рендером через `ffmpeg`, которого у сайта нет
([TOOLS_VOICEOVER_PLAN.md §8.3](./TOOLS_VOICEOVER_PLAN.md)).

## 1.10. Интерфейс

Зоны те же, что у редактора титров, с двумя отличиями:

- **зона 3** — не «оригинал ↔ перевод», а «титр (только чтение) ↔ текст для синтеза ↔
  состояние озвучки»; сетка `44px 150px 1fr 1fr 168px`;
- **зона 4** — слои перевёрнуты: титры уходят на задний план полупрозрачными блоками (они
  здесь ориентир, их не двигают и не режут), тейки — на переднем.

Клавиши по умолчанию: `G` озвучить, `F` вписать, `Delete` убрать версию (`Shift` — все
версии реплики), `Space` play/pause, `O` слушать оригинал, `W` общая волна. Все
переназначаются, справка — `F1`. `Backspace` работает вместо `Delete`: на ноутбучных
клавиатурах Apple кнопка с надписью delete присылает именно его.

Настройки экземпляра: высота дорожек, кегль, прилипание, число параллельных генераций,
две половины авто-вписывания, формат экспорта (пока только WAV), раскладка клавиш.

# Часть II. Файлы в папке задачи

Тейки лежат **внутри папки дорожки**, а не в общей `voice/` рядом с ней:

```
OUT/<задача>/
  dialog.json
  01/
    orig.srt, es.srt        ← сырьё титров: инструмент не трогает
    audio.wav               ← стем персонажа: не трогает
    voice/
      c001-1.wav            ← тейк: {cueId}-{номер}.wav
      c001-1.peaks.json
      c001-2.wav            ← «озвучить заново» — новый номер, старое остаётся
```

Почему так: всё про персонажа в одном месте — сырьё, стем и его озвучка; работая с
персонажем, не надо ходить по двум деревьям, а удаление дорожки убирает одну папку.
Разделение «сырьё против сгенерированного» несёт сама вложенность: `{NN}/*.srt` и
`{NN}/audio.wav` не трогает никто, `{NN}/voice/**` — наше.

Номера тейков не переиспользуются (`nextTakeNumber` считает по максимуму, а не по
количеству): иначе удалённый и заново сгенерированный тейк наложился бы на файл,
ссылку на который кто-то ещё держит.

# Часть III. Как подключить настоящего провайдера

Заглушка ([lib/tools/voice/stub.ts](../lib/tools/voice/stub.ts)) существует затем, чтобы
весь путь — клип, волна, воспроизведение, подстройка, экспорт — можно было проверить до
появления провайдера. Она отдаёт **настоящий звук**: путь-обманка вскрылась бы на первой
же реальной генерации десятком мест, которые никто не видел работающими. Речью не
притворяется (слышно тон), но длительность считается по тексту, форма волны повторяет
слова и паузы, а темп и высота у каждой генерации свои — две версии одной реплики слышно
как две разные. Случайность приходит снаружи числом `seed`, сам модуль детерминирован.

Замена — это подмена одного модуля «текст → байты»:

1. в [voice/generate/route.ts](../app/api/account/tools/%5Bid%5D/voice/generate/route.ts)
   заменить `synthesizeStub` на вызов сервиса; всё остальное в файле от провайдера не
   зависит;
2. проставить в тейке `provider` и `voiceId` вместо `"stub"` / `null`;
3. взять голос и параметры из `tracks[].voice` (`provider`, `voiceId`, `params`,
   `sample`) — поля уже есть в документе и уже правятся в панели дорожек;
4. ключи провайдера — в переменные окружения, рядом с остальными (`.env.example`);
5. если у провайдера свои форматы, кроме WAV, — добавить в `VoiceExportFormat` и в
   `render.ts` декодирование (Web Audio декодирует то, что умеет браузер);
6. если синтез идёт дольше запроса — очередь придётся переносить на сервер
   ([§1.5](#15-генерация) и ограничения ниже).

# Часть IV. Ограничения текущей версии

Список честный: это то, чего нет, а не то, что «работает частично».

| чего нет | следствие |
| --- | --- |
| настоящего синтеза | в папку пишется тон по длительности текста; проверить можно всё, кроме качества голоса |
| серверной очереди | очередь живёт в памяти вкладки: перезагрузка страницы её теряет, а спросить «что там с генерацией» негде |
| уборки невыбранных тейков в интерфейсе | `pruneTakes` и `takeFiles` в модели есть и покрыты смыслом, но ни кнопки, ни роута удаления файлов у них нет — файлы копятся по одному на попытку |
| форматов, кроме WAV | выгрузка — WAV 16 бит моно 32 кГц; mp3/opus нужен кодировщик, которого в браузере нет |
| сохранения высоты голоса при `rate ≠ 1` | ускоренный тейк в файле звучит выше, чем в превью; интерфейс предупреждает |
| записи выгрузки в `exports/` | экспорт уходит файлом в браузер, а не в папку задачи |
