# Что обработка должна положить в `OUT`

**Кому:** тому, кто настраивает граф обработки в программе и хочет, чтобы папка
задачи открылась в редакторе титров на сайте без доработок.

**Статус:** 🔧 контракт зафиксирован, ноды `audioPeaks` и `dialogDocBuild` ещё не написаны
([TOOLS_SRT_EDITOR_PLAN.md §V.4–V.5](./TOOLS_SRT_EDITOR_PLAN.md)).

Два соседних документа, и у каждого своя область:

- **этот** — папка: какие файлы, где, в каком виде и кто их создаёт;
- [DIALOG_FORMAT.md](./DIALOG_FORMAT.md) — **формат самого `dialog.json`**: поля, типы,
  правила записи и слияния. Он же контракт с локальным редактором в программе.

Правило разделения: если вопрос звучит «как называется файл и куда его класть» — сюда;
«что писать в поле» — туда.

## 1. Раскладка папки задачи

```
OUT/                                   ← корень задач проекта (настраивается, §6)
  {имя_исходника}/                     ← одна задача = одна папка = один материал
    dialog.json                        ← документ: дорожки, реплики, переводы, правила
    source.mp4                         ← кадр + общий звук
    mix.peaks.json                     ← волна общего звука
    01/                                ← папка дорожки: номер, не имя
      orig.srt                         ← сырьё: распознанный текст
      es.srt                           ← сырьё: перевод
      audio.wav                        ← только если стемы вообще есть
      audio.peaks.json                 ←   и тогда волна к ним
    02/
      …
    exports/                           ← создаёт и пересоздаёт редактор, не обработка
```

**Задача — это папка первого уровня внутри `OUT`.** Именно её человек выбирает в меню
«проект → папка задачи». Имя папки видит человек, поэтому оно должно быть узнаваемым:
имя исходника без расширения подходит, `job_8f21ac` — нет.

**Папка дорожки — номер, а не имя персонажа.** Имя живёт в документе (`tracks[].name`),
и переименование персонажа в редакторе не двигает файлы и не ломает ссылки. Номер —
две цифры с ведущим нулём (`01`, `02`), он же `tracks[].no`.

## 2. Файлы: что обязательно, а что нет

| путь | кто создаёт | обязателен | если файла нет |
|---|---|---|---|
| `dialog.json` | нода `dialogDocBuild` | **да** | папка не откроется: редактор скажет, что документа нет |
| `source.mp4` | нода экспорта видео | нет | кадр не показывается, остаются титры и таймлиния; часы берёт общий звук, а без него — программный таймер |
| `mix.peaks.json` | нода `audioPeaks` | нет | волны нет, линейка и клипы работают |
| `{no}/orig.srt` | распознавание | нет | реплики уже в документе; SRT — только след происхождения (`cues[].origin`) |
| `{no}/{lang}.srt` | перевод | нет | то же: перевод уже в документе |
| `{no}/audio.wav` | опционально, если делают стемы | нет | дорожка молчит; `solo` на ней = тишина, и редактор так и подписывает |
| `{no}/audio.peaks.json` | нода `audioPeaks` | нет | на дорожке рисуется общая волна, приглушённо и с пометкой «общая» |
| `exports/**` | **редактор**, не обработка | — | обработка сюда не пишет и отсюда не читает |

**Минимальная рабочая задача — один `dialog.json`.** Ни видео, ни звука, ни пиков:
инструмент откроется, покажет реплики и даст править текст и тайминги. Всё остальное —
удобство, а не условие. Это не оговорка на всякий случай, а рабочий режим: перевод
вычитывают и без картинки.

**Промежуточных файлов в `OUT` быть не должно.** Аудио 16 кГц, `words.json`, разметка
спикеров живут в локальной рабочей папке и вычищаются. Отсюда требование, чтобы
`dialog.json` был самодостаточным: редактор на сайте не увидит ничего, кроме этой папки.

## 3. Откуда берётся каждое поле документа

Полное описание полей — [DIALOG_FORMAT.md §3](./DIALOG_FORMAT.md). Здесь только
происхождение: что обработка обязана заполнить и чем.

| поле | откуда | если пусто |
|---|---|---|
| `media.video` | путь к экспортированному видео **относительно папки задачи** | превью без кадра |
| `media.mix` | отдельный файл общего звука, если граф его делает | звук берётся из дорожки видео |
| `media.peaks` | результат ноды `audioPeaks` по общему звуку | волны нет |
| `media.durationMs` | длительность материала | считается по последней реплике; за концом видео пропадает серая зона на таймлинии |
| `media.fps` | частота кадров исходника | покадровый шаг недоступен, шаг ±100 мс |
| `languages.original` | язык распознавания | подпись колонки «Оригинал» останется, но экспорт не будет знать язык |
| `languages.targets` | языки переводов, **в порядке колонок редактора** | человек добавит язык руками в редакторе |
| `tracks[].no` | номер папки дорожки | дорожка не соберётся |
| `tracks[].name` | имя персонажа — свойство `speakerNames` ноды | подставится `Speaker 1`, `Speaker 2` |
| `tracks[].color` | можно не задавать | редактор раздаст цвета по кругу; человек меняет их в шапке дорожки, и выбор пишется в документ |
| `tracks[].audio` / `peaks` | пути к стемам, если они есть | дорожка молчит, волна общая |
| `tracks[].diar` | движок, id спикера, средняя уверенность | фильтр «требует внимания» и сортировка по уверенности работать не будут |
| `cues[].startMs` / `endMs` | тайминги реплики, **целые миллисекунды** | реплика с некорректным интервалом отбрасывается при разборе |
| `cues[].text` | распознанный текст | пустая реплика допустима — её и заведут для правки |
| `cues[].tr[lang]` | перевод: `{ text, status }` | колонка перевода пустая, писать в неё можно |
| `cues[].status` | `auto` для машинного результата | считается `auto` |
| `cues[].origin` | `kind: "auto"`, файл и индекс исходного SRT | не будет видно, откуда пришла реплика |
| `cues[].origin.confidence` | уверенность атрибуции персонажа | фильтр по уверенности пустой |
| `rules` | свойство `rules` ноды: `maxCps`, `minDurationMs`, `minGapMs` | берутся значения по умолчанию из [DIALOG_FORMAT.md §5](./DIALOG_FORMAT.md) |

**Все пути в документе — относительные, от папки задачи, без `..`.** Абсолютный путь
или выход наверх — ошибка валидации, а не предупреждение: документ уезжает в хранилище
и открывается на другой машине.

**Порядок реплик в файле фиксирован:** `startMs`, затем `trackId`, затем `id`
([§2.4](./DIALOG_FORMAT.md)). Это не косметика: на нём держится проверка «открыл →
сохранил → файл побайтово тот же», по которой сверяются две реализации редактора.

## 4. Форматы вспомогательных файлов

### Пики (волна)

```jsonc
{ "version": 1, "pps": 50, "bits": 8, "dur": 718.4, "data": "<base64 пар min/max>" }
```

- `pps` — пар в секунду; 50 достаточно, при 320 px/с на пиксель приходится меньше пары
  и волна честно рисуется ступеньками;
- `bits` — 8 или 16; 8 хватает, файл вдвое меньше;
- `data` — пары `min`, `max` подряд, знаковые целые, нормированные к максимуму разряда;
- `dur` — длительность в секундах, дробная.

Считать пики обязана обработка. В браузере это не фолбэк, а плохой фолбэк: декодировать
десятиминутный звук — секунды фриза и сотни мегабайт памяти, и результат не переживёт
перезагрузку страницы. Файл пиков — десятки килобайт и рисуется мгновенно.

### SRT-сырьё

Читается только один раз — нодой `dialogDocBuild`, когда она собирает документ.
Ни редактор, ни экспорт эти файлы не трогают. Кодировка UTF-8, без BOM.

### Видео и звук — требование браузера

Это то место, где контракт упирается не в наши договорённости, а в плеер:

- **требование:** контейнер и кодек, которые играет браузер. Практически — `mp4` с
  `H.264` + `AAC`, либо `webm` с `VP9`/`AV1` + `Opus`. `ProRes`, `DNxHR`, `HEVC` в `mp4`,
  `mkv` — не откроются, и редактор покажет задачу без кадра;
- **требование:** `-movflags +faststart`. Без него заголовок лежит в конце файла, и
  браузер не начнёт играть, пока не скачает всё;
- **рекомендация:** отдельная копия для вычитки — 720p, ~2 Мбит/с. Файл едет из
  хранилища по сети на чужой машине, и 4K тут не даёт ничего: титры правят по звуку и
  по волне, а не по резкости кадра;
- аудио дорожек (если стемы делают) — `wav` PCM 16 бит или `mp3`/`aac`; частота любая.

Перемотка работает: сайт отдаёт подписанную ссылку прямо в хранилище, а оно поддерживает
`Range`.

## 5. Как выстроить граф

Порядок нод для основного пути (распознавание + диаризация):

1. **`transcribeVA`** в режиме `jsonfull` → `words.json` (слова с таймингами).
2. **Диаризация** → `diarization.json` (кто говорит и когда).
   Отдельная работа, [TOOLS_SRT_EDITOR_PLAN.md §V.3](./TOOLS_SRT_EDITOR_PLAN.md).
3. **Экспорт видео** для вычитки → `source.mp4` (см. требования выше).
4. **`audioPeaks`** по общему звуку → `mix.peaks.json`; по стемам, если они есть,
   → `{no}/audio.peaks.json`.
5. **`dialogDocBuild`** — финализатор: создаёт папку задачи, раскладывает файлы,
   собирает `dialog.json`.

Простой путь, когда SRT уже готовы: шаги 1–2 не нужны, `dialogDocBuild` разбирает готовые
`orig.srt` и `{lang}.srt`.

Свойства `dialogDocBuild`, которые надо выставить осознанно:

| свойство | что задать |
|---|---|
| `taskPath` | `$localFolder/OUT/$clearName` — имя папки задачи видит человек |
| `speakerNames` | имена персонажей по порядку дорожек через запятую |
| `langFromName` | включить, если язык перевода закодирован в имени файла (`_es`, `.es`) |
| `origSuffix` | как узнать оригинальный SRT среди остальных |
| `rules` | `maxCps`, `minDurationMs`, `minGapMs` под конкретный материал |

## 6. Повторный прогон: нода — первый автор, а не владелец

Прогон может случиться после того, как человек уже правил реплики. Поэтому
`dialogDocBuild` при существующем `dialog.json`:

- **дописывает** новые дорожки и новые реплики;
- **не трогает** существующие реплики, даже если распознавание изменилось;
- **не воскрешает** то, что лежит в `removed`;
- **не трогает** `exports/`.

Перезапись уничтожила бы работу человека, а отказ дописывать оставил бы новые дорожки
невидимыми. Подробности слияния — [DIALOG_FORMAT.md §8–9](./DIALOG_FORMAT.md).

## 6a. Редактор тоже пишет в `dialog.json`

Файл в папке — не только результат обработки, но и рабочий документ человека.
Редактор на сайте сохраняет правки сам, без кнопки, и при каждой записи:

- увеличивает `revision` на единицу;
- ставит `updatedAt` (UTC, ISO) и `updatedBy` — почту того, кто правил;
- ставит `producer` вида `innovation-hub/srt-editor 0.1`;
- пишет файл в каноническом виде: порядок ключей из §3 контракта формата, отступ два
  пробела, перевод строки в конце, реплики отсортированы по §2.4;
- **сохраняет все поля, которых не знает** — на уровне документа, дорожки и реплики
  (правило §2.5). Поле, добавленное обработкой под озвучку, не потеряется.

Запись условная, по ETag: если между чтением и записью документ изменился, сайт перечитывает
папку и сливает версии по §8 контракта формата, а не затирает чужое.

**Что из этого следует для обработки.** `revision` — не украшение: по нему определяется,
кто новее. Нода обязана его сохранять и увеличивать при дописывании, а не сбрасывать в ноль
и не выставлять фиксированное значение. Такой сброс выглядит для сайта как «версия старше
нашей» и приведёт к слиянию там, где слияния не требовалось.

## 7. Чего обработка делать не должна

- писать в `exports/` — эту папку редактор пересоздаёт целиком;
- перезаписывать `dialog.json` целиком (см. §6);
- класть в `OUT` промежуточные файлы: они переживут задачу и запутают того, кто откроет
  папку через месяц;
- полагаться на имя персонажа в путях: имя меняется в редакторе, номер — нет;
- писать абсолютные пути в документ;
- сбрасывать `revision` (см. §6a);
- перезаписывать `updatedBy` человека своим значением при дописывании: там должен остаться
  автор последней правки.

## 8. Нестандартная раскладка

Раскладку задаёт граф, и она может быть любой — редактор к этому готов с двух сторон:

- **правило чтения `OUT`** у каждого проекта своё, в настройках инструмента: «папки
  первого уровня» (по умолчанию), «только `*.srt`», «всё содержимое». Так проект, где
  задача — это не папка, всё равно виден в меню;
- **если `dialog.json` в папке нет**, инструмент предлагает собрать его на месте по
  шаблону путей из настроек экземпляра и сохранить в папку — дальше работа идёт как
  обычно.

Второе — аварийный путь, а не замена ноде: имя персонажа взять негде, и дорожки получат
номера вместо имён.

## 9. Проверка перед сдачей

```bash
# документ по контракту: ошибки, замечания, порядок реплик, побайтовая запись
node scripts/check-dialog-doc.mjs путь/к/OUT/задача/dialog.json

# можно сразу папкой или несколькими
node scripts/check-dialog-doc.mjs путь/к/OUT
```

Скрипт различает **ошибки** (файл невалиден, открывать нельзя) и **замечания**
(нарушены правила материала — показать человеку, но не отказывать).

Эталонный комплект, на котором собран и проверен редактор:

```bash
node scripts/make-dialog-fixture.mjs ./dialog-fixture            # как в жизни: общий звук + титры
node scripts/make-dialog-fixture.mjs ./dialog-fixture --stems    # плюс аудио по персонажам
node scripts/make-dialog-fixture.mjs ./dialog-fixture --no-media # только документ и титры
```

**Чек-лист приёмки задачи:**

- [ ] `dialog.json` лежит в корне папки задачи и проходит `check-dialog-doc`;
- [ ] имя папки задачи узнаваемо человеком;
- [ ] папки дорожек — номера с ведущим нулём, `tracks[].no` совпадает с именем папки;
- [ ] `tracks[].name` — имена персонажей, а не `Speaker 1`;
- [ ] все пути в документе относительные, файлы по ним существуют;
- [ ] видео играется в браузере и с `faststart`;
- [ ] `mix.peaks.json` на месте, `pps` не меньше 50;
- [ ] `languages.targets` перечисляет ровно те языки, переводы которых есть;
- [ ] `origin` заполнен у всех реплик;
- [ ] в `OUT` нет промежуточных файлов, `exports/` обработкой не тронута;
- [ ] повторный прогон на уже правленной задаче ничего не потерял.
